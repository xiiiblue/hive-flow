# HiveFlow：把反馈接到有证据的交付

**[官网与介绍手册](https://www.bluexiii.com/flow/) · [快速开始](docs/维护/EXP-004-快速开始与采用方式.md) · [完整流程](docs/11-手册/05-自动化手册/03-流程总览：一条反馈怎样走到交付.md) · [Apache-2.0](LICENSE)**

HiveFlow是一套让人和智能体协同处理反馈的方法、规则与离线参考工具。它把“用户说了什么”“负责人决定做什么”“开发实际完成什么”和“结果怎样回到原反馈者”连起来，让工作可以核对、交接和恢复。

它源自蜂巢实践，复用理解助手、GitHub Issues、Codex和消息桥接，不提供新的常驻调度器。来源实例由云端dots调查与登记Issue，再交接到Director的MacMini上的Codex；其他项目可以借用方法和格式，按自己的宿主、身份、工具和权限完成接入。

本仓库提供完整介绍、正式规则的公开参考版和离线工具，不需要访问私有HiveOS就能阅读、检查和运行合成演练。**它不是安装后即自动处理业务的服务，当前业务自动执行尚未启用。**

## 它解决什么问题

|容易混淆的事情|HiveFlow怎样处理|
|---|---|
|建了Issue，是不是就能开工|登记、采纳与实施授权分别核验|
|手动就只能开PR，定时就会自动上线|启动方式与交付终点分开选择，共四种组合|
|代码合并了，是否已经交付|检查、合并、部署、验收、正式记录和通知各自留证|
|通知失败或结果未知，要不要再做一次|先核实原动作；不重复开发、不换标识或通道盲目重发|
|隔天换了Agent，怎样继续|固定事项、版本、已有候选、权限与已观察结果，按事实接续|

## 五分钟开始

需要Git和Python3.9+，离线检查只使用Python标准库，不需要安装第三方Python包、运行模型或提供Token。完整离线工具面向macOS/Linux，源码缓存使用POSIX文件锁，尚未提供Windows适配。

```sh
git clone https://github.com/xiiiblue/hive-flow.git
cd hive-flow
python3 -B scripts/check_repository.py
python3 -B scripts/hiveflow/test_spec_loading.py
python3 -B -m unittest discover -s scripts/hiveflow -p 'test_*.py'
python3 -B scripts/test_export.py
```

macOS先设`export TMPDIR=/tmp`。这些命令核对文档与来源摘要，并在临时目录中测试加载、状态、数据格式和过滤规则；不会建Issue、发送回执、创建原生任务或执行部署。

再运行一次保持关闭的采纳记录演示：

```sh
printf '%s\n' '{"operation":"initialize","record":null,"expectedBlobSHA":null,"observedBlobSHA":null}' | python3 -B scripts/hiveflow/adoption_record.py
```

它只输出一份`executionEnabled=false`的JSON提案。`write=true`表示调用方下一步可以准备写入的提案，**工具自身不写文件、不调用GitHub，也不产生执行权限**。完整解释与交付格式示例见[快速开始](docs/维护/EXP-004-快速开始与采用方式.md)。

## 四种组合，Director何时介入

|本地启动|PR待审|完整交付|
|---|---|---|
|手动|Director发起1次；完成开发、检查与PR后停止，再介入1次处理合并、部署|Director明确完整范围并授权1次，正常路径推进到约定交付|
|原生定时任务|有效配置内无需逐单发起；每单PR完成后仍需介入1次|有效配置内无需逐单发起或例行确认后续步骤|

这里只统计Issue进入本地研发后的阶段。源头采纳、定时配置批准与实际启用另计；完整交付仍须真实完成规定审阅和约定验收。约定本人验收、新的重要取舍或超出授权时，按实际情况再介入，不能以次数代替真实授权。

## 工具可以做什么

|工具|用途|需要注意|
|---|---|---|
|`check_repository.py`|核对公开副本摘要、链接与常见敏感形态|只检查本地，不认证全部历史或外部权限|
|`validate_delivery.py`|核对交付记录及PR唤醒文本的严格结构|不认证作者、证据或交付成功，不发消息|
|`adoption_record.py`|演示空闲、采纳、认领、取消及结果提案|来源实例的仓库/控制位置固定；不是任意项目可直接启用的调度器|
|`source_snapshot.py`|按固定版本清单过滤文本源码、核对缓存和检索所需规则|输入来自调用方已有权限；不联网拉取，不执行业务代码|
|`test_*.py`|合成输入下的正例与拒绝路径|不替代真实宿主、账户、桥接及恢复验证|

接入其他项目时，先选择适用方法，核验目标仓库、身份、权限和写入副作用；保留自己的AGENTS与环境规则。内置HiveOS适配是参考实例，不应直接替换字符串后就当作真实授权。

## 来源、边界与维护关系

内容来自HiveOS提交`5d71f33176eb4ab4788e1c875b1a3eb3bf5bd22a`。上游规范是蜂巢实例的权威执行规则；本仓库是经过公开整理的参考版本。来源文档中的Accepted、Review、日期和现场状态属于原实例，其他项目按自己的实际证据确认。

[来源清单](export-manifest.json)分别记录原始字节、公开整理后字节和调整原因。公开整理包括导航、许可语境与示例环境名称，不导入业务源码、凭据、原始消息或运行配置。维护链路为规范→介绍→网站→独立仓库；修改来源规则与修复本仓库公开说明分别记录。

HiveFlow与[ACDL](https://github.com/xiiiblue/hive-acdl)配合：ACDL组织工程研发，HiveFlow衔接反馈、授权、交付终点与结果回执。可独立采用，不继承任何来源项目的工具权限。
