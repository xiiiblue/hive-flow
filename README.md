# HiveFlow

HiveFlow 是给 dots、未来也可给 Hermes 等智能体阅读和遵循的**可移植研发流程规范**，不是运行在 PVE 上的业务应用或调度服务。HiveOS 是首个使用场景，不能写成规范的固定依赖。规范本身不提供授权：平台规则、真实工具权限和用户有效授权优先。

## 阅读入口

- [核心流程、角色与授权](docs/WORKFLOW.md)：从反馈、采纳、执行到验收回滚。
- [手动和自动模式](docs/AUTO_MODE.md)：由智能体原生任务管理明确期限的会话，扫描授权范围内已同意事项并推进，无需用户逐项手工入队。
- [简洁中文交互](docs/OWNER_COMMANDS.md)：一次方案审批覆盖已列明的修改、测试及交付动作。
- [dots / Hermes 适配](docs/ADAPTERS.md)：分开核验意图、关联和权限，只使用真实工具能力。
- [分层验收用例](docs/ACCEPTANCE.md)：设计审查、合成演练和真实联调分别记录，含自然表达反例与基准变化核对。
- [切换记录与验收边界](docs/MIGRATION.md)：已完成的独立 bridge 切换、历史保全、待验证项目与回滚。

## 工具分工

智能体理解研发业务，使用其已授权的 GitHub、消息、任务和开发工具执行规范。dots 的定时启动与关闭使用 dots 自身云端任务能力；不再把 HiveFlow 部署为常驻应用或新建第二个调度器。

`wecom-slack-bridge` 是独立通用开源桥接，无 HiveFlow 也能使用。它只负责通用来源核验、固定受众、会话对应、可靠投递与去重，不解释 Issue、采纳、审批、执行、仓库或研发模式指令。用户消息由智能体理解；不得把业务处理重新塞回 bridge。

## 当前本人审批渠道

**所有向本人询问、评审、授权和本人结果回传都在 dots 原生本人主对话完成，这是当前唯一审批入口。** 保留短摘要、自然确认、完整计划唯一关联和已批准范围内一次授权；不再向企微发审批或要求两处重复确认。

企微保留群反馈、普通咨询及原授权内适宜公开的建单/业务状态回执。历史企微审批不重放、不转成新许可；原路径暂不启用，未来 Hermes 仅待适配。bridge 通用 notify/回复功能继续独立保留。#84 已完成未部署合并，后续部署未授权，自动开发关闭；渠道选择本身不是实施授权。

## 已部署能力与执行边界

最近一次发布验收记录：独立 bridge `7ee2f75` 已运行，68 项本地及目标 Linux 检查与 CI 通过；不再从 HiveFlow 组合入口启动。固定本人主动通知、短编号回复关联已实测一个会话来回，后续回执获得平台 ACK；不能把最后一个 ACK 当作用户已看到的证明。

[历史文档存档](docs/LEGACY_APPLICATION.md)、[旧手动应用协议](docs/MANUAL_EXECUTION.md)、[旧控制协议](docs/EXECUTION_CONTROL.md)仅用于保全、核验和受控回退。旧 record-only 决定及旧方案/许可不自动升级为当前执行授权。
