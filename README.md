# HiveFlow

HiveFlow 是围绕 GitHub Issue 的可复用协作工作流项目，沿用现有 ACDL 协作标准。它是独立的第二项副产品；HiveOS 是首个使用场景，不是硬编码依赖。

## 当前状态

这是本地初始项目骨架与边界设计。控制基础模块由现有实现提取，仍是**未接入的独立模块**，默认 `executionReady: false`。它不是在线扫描器、执行器或完整自动开发流水线。测试结果须以实际测试输出为准，单元测试不能证明端到端能力已启用。

项目品牌为 HiveFlow，仓库名为 `hive-flow`；私有仓库已由用户创建。本目录的准备不代表已经推送、发布或部署；此处不假设任何开源许可证。

## 职责边界

- **HiveFlow**：GitHub Issue 提案与决定、不可变 Issue 标识与版本关系、执行授权、模式控制、额度门槛、任务认领与执行结果。
- **消息桥接器**：通用传输、身份认证、路由、发件箱及传输去重。HiveFlow 消费可信的身份与投递上下文，并独立核验业务权限。
- **执行适配器（待实现）**：核验真实操作者与额度来源，强制执行仓库及文件范围，逐步检查授权；控制模块本身不执行这些操作。

这是目标所有权边界，不是已经完成的数据迁移。生产桥接器中的 Issue 提案、决定及关联投递记录必须保留，直到导出、导入、核对和切换均完成并通过验收。不得直接删除旧表或把待处理批准丢弃。

## 默认安全行为

手动模式默认开启；自动模式需要明确授权并设置期限。拟议自动扫描每 10 分钟一次，同时最多一个任务。额度剩余不高于 5%、未知或过期时停止新任务。现有 `decision_record_only: true` 的批准仅留档，永远不能自动升级成执行许可。部署须单独授权。

详细语义见 [工作流约定](docs/WORKFLOW.md)，安全提取步骤见 [迁移计划](docs/MIGRATION.md)。

## 最小路线图

1. 固化边界、提取休眠控制模块与单元测试，保持生产行为不变。
2. 实现并离线验证 Issue 数据导出/导入与幂等对账，保留回退路径。
3. 经明确授权进行单写者切换，验证无重复消息、重复决定或遗失待处理批准。
4. 分别接入可信控制入口、额度、共享认领、扫描与执行适配器；先手动验收，再单独批准有期限的自动运行。部署仍是独立阶段。
