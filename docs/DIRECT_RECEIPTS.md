# Codex 直连回执契约（未部署、未启用）

本页描述已批准开发、仍待独立审核和部署批准的默认关闭能力，不是现网地址、开放端口、网络许可或已完成联调。它不启用自动开发，不创建账号、令牌、调度或第二个服务。原来的 GitHub 完成评论 → dots 核验 → 原群回执路径继续按 [手动交付契约](MANUAL_DELIVERY.md)执行；不能因为代码存在就切换路径。

## 调用边界

后续只有本人另行批准实际部署、固定监听地址/端口、允许来源、仓库和公开范围，并验证真实网络边界后，Codex 才可在本次有效任务范围内向 bridge 提交回执。当前服务没有 HTTP 监听，新代码默认不监听；不得从 Issue、附件或评论取得地址、接收群或网络配置。

这个简单入口不提供账号/token 或应用身份认证，只按真实 TCP 来源 IP、专用仓库白名单和已有有效来源绑定准入。私网地址不能证明“只有 Codex 可达”，同来源机器的其他进程、NAT 后的其他可达者或被入侵设备也可能提交正文、查询状态或抢占 deliveryId。明文 HTTP 不保证防窃听/篡改。启用前须接受并核实该具体信任边界，不能为凑通路关闭安全配置、生成凭据或扩大持久访问。

HTTP 不伪造 Slack bot/user/channel/root 身份；只消费由既有可信 intake 建立的绑定，不能绑定、迁移、撤销或指定群。有效绑定须继续通过原 owner/channel/robot/responder 和群/仓库白名单校验。缺失、过期历史无证明、已撤销或身份配置变化时停止，不从群名/URL/正文补建。直接调用并不使材料成为可信指令，也不替代部署/验收及允许公开内容的判断。

## 两个操作与统一状态

桥接公开的通用 [接口定义](https://github.com/xiiiblue/wecom-slack-bridge/blob/d9c677488c8ddbd323b51adccf5415eefd769270/docs/HTTP_RECEIPTS.md)使用合成示例，不含本业务配置。候选代码为 `d9c677488c8ddbd323b51adccf5415eefd769270`，尚未合并、部署或启用；实际接入须固定独立审核的完整 commit；分支代码、文档提交、部署、网络验证和平台验收分别记录。

- `POST /v1/receipts`：严格 JSON 仅 `repository, issue, deliveryId, text`。
- `POST /v1/receipts/status`：严格 JSON 仅 `repository, issue, deliveryId`，不产生平台消息。

两者均要求准确 Content-Type、Content-Length 和配置中的 Host；拒绝 Origin、编码/分块传输、重复或额外字段、嵌套对象、任意收件人/命令参数。HTTP body 上限 16384 字节，单条公开正文上限 3000 UTF-8 字节，具有限时和连接数上限。仅允许显式来源 IP 与固定仓库，仓库还须在现有 feedback 白名单中。不能由请求关闭这些校验。

复用同一私有 SQLite 的绑定、全局稳定 deliveryId、内容摘要、事务、队列、频控和出站复核，不增加平行台账或另一写者。同 ID/绑定/正文不重复入队，不同正文/绑定冲突拒绝；HTTP 正文按字面文本，与 Slack 路径既有解码后的文本比较。响应只含状态或通用错误，不返回群、发送者、根、身份、凭据或原始日志。

HTTP `accepted` 只证明持久接收或识别到同一既有交付；同时返回的当前 delivery 可能 pending、wecom_ack 或 unknown，不意味着又发送一次。状态查询的 wecom_ack 是企微 ACK，不是用户已读或产品可用；unknown、not_found、拒绝和超时均不得据以盲重放。发送中崩溃重启仍转 unknown，沿用阻断后续同绑定群 lane 的机制。失效绑定的状态查询会拒绝，不抹去原私有证据；必要时只读核验受控记录。

## 业务事实与回执分离

GitHub 保留统一主交付事实及稳定 deliveryId。仅实现、测试、开 PR 时仍报告 PR 待审，不发最终完成回执或 `HiveFlow delivery v1`。最终通知须满足原契约的真实关联合并 commit、所需检查、实际部署或明确 not_required、验收和本次授权；schema 不扩展。业务证据/公开摘要由获准调用方独立核验，通用 bridge 不访问 GitHub或批准业务。

未来经明确批准选择直连发送时，协调者仍可能消费 GitHub 完成事件；必须沿用同 deliveryId、同一已审核正文，先核验既有发送状态，避免重复通知或内容冲突。不得未经核验让两条路径各自发送或换 ID。当前没有为此修改任何监听或自动任务，也没有启用自动切换/回退。

通知拒绝、审批受阻、未知或无绑定不重做开发、不换入口重发；人工接手见 [通知非阻塞](MANUAL_DELIVERY.md#通知非阻塞与人工接手)。特别是此前已被拒绝的合成发送，不能用新入口重试、搬运旧绑定/ID或扩大解释原许可。
