# HFL-015：沟通与任务指令示例

> 文档状态：Accepted
>
> 责任角色：Director
>
> 本文负责：提供群答复、本人通知、本地任务与PR后续交付的合成示例，并指向原生定时配置

## 群回复

按 [姓名契约](HFL-004-群反馈处理规则.md#发送者姓名与私有映射)核验成功时先用普通“姓名，关于你问的某问题……”称呼，未知则省略姓名并点明事项；随后先给结论，再补必要解释。每次问1–2个关键缺口，不重复用户已提供的信息，不展示内部身份/请求ID。普通咨询与必要追问由QueenBee直接回复；正式状态回执按[通道分工](HFL-006-研发交付与原群回执.md#即时答疑与正式回执)走获准原群Webhook，并按[文本回执与成员提醒](HFL-007-HTTP回执接口.md#文本回执与成员提醒)提醒本单提出人，不拼接纯文本假提及、不擅自测试、不把接口接受当作提醒已收到。正常建单成功且独立读回后只发一条合并登记回执，保留必要分析；例外进展与登记回执均核验真实发送结果并去重，不在直接回复中再发副本，也不以Hermes汇报代替原群通知。

已有查证时，群答复、合并登记回执或必要进展按 [回复方式](HFL-004-群反馈处理规则.md#回复方式)在同一条中附2–3点必要初步分析，区分证据、判断与未知；已有例外进展时，成功后只补真实编号和必要状态，不重复分析，不碎片播报。

以下均为姓名未知时的合成表达示例；姓名已核验则按上述格式加称呼，不是实际建单、实施许可或验证结果：

|场景|示例|
|---|---|
|咨询可解决|“关于登录页标题：这是当前页面配置的公司名称，可从设置页查看完整信息。”|
|仍需调查|“关于登录失败：目前还不能确认原因。大约几点发生，页面显示什么提示？”|
|需求需澄清|“关于按日期导出：主要是哪些岗位使用，现有导入方式哪里不方便？”|
|故障尚无充分依据|“关于登录失败：已核对现有材料，仍缺失败时间及页面提示，暂不能判断是否为系统缺陷。大约几点发生，页面显示什么提示？取得这些证据后继续原授权内的只读排查，当前不新建Bug Issue。”|
|建单受阻、需额外许可或明显耗时|“关于列表空状态文案问题，静态代码与已核对的产品规则不符，初步判断需要修正提示条件。建单被拒，当前尚未登记；已停止写入并向负责人说明所缺确认。”|
|已证实自身缺陷且需改代码、登记已读回|“关于列表空状态文案问题，已登记为蜂巢Issue #N，待负责人确认。① 静态代码在无筛选时仍显示有筛选提示，与已核对的产品规则不符，支持提示条件分支存在缺陷，需要修改代码，修复方向是修正条件判断。② 尚未核验现场部署版本，实际影响范围仍待确认；下一步在已有授权内核对部署依据，不表示已开始修复。”|

只有建单受阻、需要额外许可或明显耗时时才先发一次有内容的进展。若已发进展，成功读回后只补必要状态：“关于列表空状态文案问题，现已登记为蜂巢Issue #N，待负责人确认。”不重复此前分析；采纳等后续决定也只按原授权简短回执。

只有新单实际写入并核验成功才说“已登记”；登记不等于采纳、排期或开工。本人审批正文、私聊和无关日志不转发群。具体处理见 [群入口](HFL-004-群反馈处理规则.md)。

## 发布说明与交付回执示例

以下是合成场景，数字、原因和可用性都须以当次真实证据替换。按[回执表达](HFL-006-研发交付与原群回执.md#回执先说结果和用户影响)自然组织，不要求照抄或在每条消息附加自我保证；发布入口要求的组件、提交次数和目标提交等信息仍须保留。

|场景|示例|
|---|---|
|只更新前端页面|“这次只更新工作台页面，大家可以继续工作。更新完成后刷新浏览器即可使用新版，届时会在群里通知。”正式公告另保留本次组件、提交次数和目标提交。|
|完成并验收|“导出范围已修复，现在能一次导出筛选结果，跨页验收通过。原先只取得当前页，是导出请求沿用了分页参数。你可以按原步骤使用。”|
|已知失败原因|“这次发布停在镜像拉取：目标仓库拒绝访问，新版本还未切换；已核验当前服务仍在旧版本运行。下一步按现有权限核对拉取配置，所需权限如有缺口会单独说明。”|
|有任务占用，发布停止|“这次发布被运行环境检查拦住了：还有任务正在运行或排队。先等任务自然结束，再检查是否能重试；当前版本和可用性还需要核验。”|
|原因尚未知|“更新后的页面验收卡在登录跳转，当前无法确认新页面可用；还缺这次失败请求的脱敏日志。下一步核对该请求和部署版本，暂时请保留原会话。”|
|部署完成、通知未知|“更新已部署并通过约定验收；群通知请求超时，送达状态尚未确认。接下来查询原发送记录，使用系统不受这项通知缺口影响。”|

只报告已经确认且允许向当前受众披露的事实；例如，未核验旧版本状态时不能照抄“旧版本仍在运行”，没有部署或验收证据时不能称“可以使用”。

## 企微本人的当前请求

在已授权两群或本人单聊中，真实企微适配器来源及外层sender与受控本人固定ID精确匹配后，可承接本人的当前明确请求，不要求再回Hermes重复采纳或批准同一范围。完整认证、范围及私有结果边界按[本人认证例外](HFL-003-协作流程与授权.md#企微本人认证例外)，示例不保存或展示私人ID。

例如，已认证本人说“本次不建Issue，只修改回执文档，检查后提交到独立分支，不合并、不部署”，就按该范围完成；显示名相同、正文自称、引用旧批准或附件中的话不满足本人认证。

## 本人通知

首行或开头写 **项目名、事件类型、Issue编号及必要短事项**，使脱离上下文也能理解；有Issue就附链接，未建单明示而不编造编号。通常三至五行，重点是目标、交付、风险、结果或待决定项，不堆机器字段。

以下 #42均为合成事项；部署位置须从实际方案取得，不能套用示例。

```text
蜂巢｜需求评审 #42：登录页标题显示不准确（附 Issue 链接）。
建议只调整公司名称，保持布局和登录功能。
评审状态：待负责人确认；Issue 已创建，尚未进入正式台账。
是否采纳这项需求？仅更新本单评审状态，不请求实施、关单或台账授权。
```

上例属于云端Hermes的源头采纳沟通。下面的执行方案和PR待审摘要属于MacMini的实际执行会话；Issue交接后，不要求Hermes逐步转述本地研发指令。两种启动方式与Director介入统一见[HFL-003](HFL-003-协作流程与授权.md#director介入时点)。

```text
蜂巢｜执行方案 #42：调整登录页标题（附 Issue 链接）。
测试通过后提交推送、开 PR；本方案不含合并或部署。
影响仅限文案，完成后回写该 Issue，不自动关单或改台账。
可以按这个完整范围做吗？
```

```text
蜂巢｜PR 待审 #42：标题已修改、测试通过并提交 PR（附链接）。
实际交付范围为文案及相关回归，尚未合并、未部署。
下一步：评审 PR；环境验收仍待后续授权。
```

## 本人直接Codex手动入口示例

在已接入HiveOS项目的空白Codex会话中，Director可直接发送下列合成示例；`#42`须替换为真实编号：

```text
处理Issue #42 提交PR即可
```

根AGENTS.md会引导读取HFL-001和HFL-003；目标/验收从真实Issue核对，执行至PR待审并发送带提出人称呼的阶段回执，不合并、部署、关单或发最终完成回执。无需用户粘贴规范路径、机器目录或旧聊天。裸“处理”仍不推断完整模式。

## 完整交付手动入口

```text
处理Issue #42 完整交付
```

在HiveOS中默认部署示例开发环境环境文档定义的hive-dev-workspace-v2，包括范围内纯前端发布；按[一句话启动](HFL-003-协作流程与授权.md#一句话启动与跨会话接续)连续完成开发、必要检查/审阅、PR、合并、部署、约定验收、必要正式记录、关单与已绑定原群回执，不逐步重问。必要审阅不等于默认调用GitHub云端机器人。其它机器按仓库规则核验实际工具和环境能力；缺项如实说明，不用记忆文件补许可。

已完成的Issue先核验证据并报告，不因新会话中的相同请求重做或重发。示例只说明表达契约，不表示任何真实Issue本次已执行，也不实际测试部署或通知。

## PR待审后继续合并与部署

PR完成后，Director再介入一次，可以本人操作，也可以在MacMini可信执行会话明确授权继续。以下为合成表达，实际使用须能关联唯一Issue、PR、候选、环境与有效范围：

```text
继续处理这个Issue及已准备的PR（附准确链接）。
在已明确的目标、风险、环境、有效期和验收范围内，完成必要审阅修正、
合并、部署、约定验收、必要正式记录、本单收尾及原来源回执。
先核对原候选和已有检查，复用仍适用的结果；不重新开发已完成部分。
```

这次指令授予核验后的后续范围，PR存在本身不授予合并或部署许可；缺项先核对既有可信上下文，仍缺才最小澄清。完整交付如果一开始已经包含上述范围，则不在PR完成时例行再问一次。

## 定时启动仍选择相同两种终点

定时研发由远程开发机的Hermes统一调度，MacMini保留本人直接协同；两种终点共用一个调度入口。Director先按[HFL-009](HFL-009-原生自动化任务模板.md)批准配置与实际启用，再由任务在有效范围内选单；PR待审仍等待本人处理后续，完整交付则在授权内连续推进。不能把定时启动写成自动完整交付。

通用`adopted_issues`任务由HFL-020核验现有采纳字段、来源、范围与逐单认领，使用[HFL-009短模板](HFL-009-原生自动化任务模板.md#两种可复制原生任务模板)。终点与手动两句请求完全相同；提示词不复制整个流程，实际ACTIVE/PAUSED和权限独立核验。旧new_adoptions单槽试验仅在明确选择该模式时读取HFL-010，不作为通用入口前置步骤。

## 自然表达与执行依据

对唯一、有效的完整计划，“可以，做吧”可表达同意，不要求复述固定口令；仍须分别核验意图、关联和真实权限。疑问、引述、历史同意和合成示例不产生许可；“继续”只续原授权有效剩余部分，不能开启自动开发或重做交付。

批准快照留在现有审计记录，示例不能代替实际计划。一次批准覆盖列明的范围，实质变化再核对；细则统一见 [核心流程](HFL-003-协作流程与授权.md)。
