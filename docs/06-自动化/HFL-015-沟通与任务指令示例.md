# HFL-015：沟通与任务指令示例

> 文档状态：Accepted
>
> 责任角色：Director
>
> 本文负责：提供群答复、本人通知、本地任务与PR后续交付的合成示例，并指向原生定时配置

## 群回复

按 [姓名契约](HFL-004-群反馈处理规则.md#发送者姓名与私有映射)核验成功时先用普通“姓名，关于你问的某问题……”称呼，未知则省略姓名并点明事项；随后先给结论或当前已确认状态，再补必要解释。每次问1–2个关键缺口，不重复用户已提供的信息；不展示内部身份/请求ID，不做真正提及、纯文本 @ 或 @ 测试，不承诺提醒已送达。桥接负责传统收到回执，dots不另发重复的收到确认；登记回执另按 [查重与可读登记](HFL-004-群反馈处理规则.md#查重与可读登记)检查原根并完成，不以dots汇报代替。

已有查证时，群答复和登记回执按 [回复方式](HFL-004-群反馈处理规则.md#回复方式)在同一条中附2–3点必要初步分析，区分证据、判断与未知；不只报编号，不碎片播报。

以下均为姓名未知时的合成表达示例；姓名已核验则按上述格式加称呼，不是实际建单、实施许可或验证结果：

|场景|示例|
|---|---|
|咨询可解决|“关于登录页标题：这是当前页面配置的公司名称，可从设置页查看完整信息。”|
|仍需调查|“关于登录失败：目前还不能确认原因。大约几点发生，页面显示什么提示？”|
|需求需澄清|“关于按日期导出：主要是哪些岗位使用，现有导入方式哪里不方便？”|
|故障尚无充分依据|“关于登录失败：已核对现有材料，仍缺失败时间及页面提示，暂不能判断是否为系统缺陷。大约几点发生，页面显示什么提示？取得这些证据后继续原授权内的只读排查，当前不新建Bug Issue。”|
|已证实自身缺陷且需改代码、登记已读回|“关于列表空状态文案问题，已登记为蜂巢Issue #N，待负责人确认。① 静态代码在无筛选时仍显示有筛选提示，与已核对的产品规则不符，支持提示条件分支存在缺陷，需要修改代码，修复方向是修正条件判断。② 尚未核验现场部署版本，实际影响范围仍待确认；下一步在已有授权内核对部署依据，不表示已开始修复。”|

只有新单实际写入并核验成功才说“已登记”；登记不等于采纳、排期或开工。本人审批正文、私聊和无关日志不转发群。具体处理见 [群入口](HFL-004-群反馈处理规则.md)。

## 本人通知

首行或开头写 **项目名、事件类型、Issue编号及必要短事项**，使脱离上下文也能理解；有Issue就附链接，未建单明示而不编造编号。通常三至五行，重点是目标、交付、风险、结果或待决定项，不堆机器字段。

以下 #42均为合成事项；部署位置须从实际方案取得，不能套用示例。

```text
蜂巢｜需求评审 #42：登录页标题显示不准确（附 Issue 链接）。
建议只调整公司名称，保持布局和登录功能。
评审状态：待负责人确认；Issue 已创建，尚未进入正式台账。
是否采纳这项需求？仅更新本单评审状态，不请求实施、关单或台账授权。
```

上例属于云端dots的源头采纳沟通。下面的执行方案和PR待审摘要属于MacMini的实际执行会话；Issue交接后，不要求dots逐步转述本地研发指令。两种启动方式与Director介入统一见[HFL-003](HFL-003-协作流程与授权.md#director介入时点)。

```text
蜂巢｜执行方案 #42：调整登录页标题（附 Issue 链接）。
测试通过后提交推送、开 PR；本方案不含合并或部署。
影响仅限文案，完成后回写该 Issue，不自动关单或改台账。
可以按这个完整范围做吗？
```

```text
蜂巢｜PR 待审 #42：标题已修改、测试通过并提交 PR（附链接）。
实际交付范围为文案及相关回归，尚未合并、未部署。
下一步：评审 PR；环境验收仍待后续授权。
```

## 本人直接Codex手动入口示例

本人可在自己的Mac mini Codex会话发起以下请求，指定实际HiveOS Issue链接；这只是手动任务发起示例，不把任何已有Issue当成本次执行任务，也不授予未列明步骤：

```text
先按HiveOS当前同仓固定版本的HFL-001加载delivery规范，本地项目优先读取。
请处理 HiveOS Issue #N（附准确仓库链接），范围包括修改、测试、提交、
推送及创建 PR，完成后给我审阅。先核对当前规范、项目规则、实际现状、
重复或在途工作，目标与验收缺项先澄清。此范围不含合并、部署、关单或
正式台账；完成报告“PR 待审”，不发送最终完成唤醒。
```

实际执行宿主仍按 [本人直接入口](HFL-003-协作流程与授权.md#本人直接codex手动入口)核验本人、工具权限和范围；已有批准的同范围步骤不重复确认，无须迁回dots重批；裸“处理”不产生未来合并、部署、关单或台账许可。示例不表示新会话已自动加载规范、接通工具或通过现场入口验收，缺口须实际核对。

实际交付及当次约定验收完成后，按 [默认收尾](HFL-006-研发交付与原群回执.md#默认交付收尾)自行查询可信来源并生成脱敏HTTP回执，无须追加提示；先查询同deliveryId，已发跳过、pending跟进、unknown不重发/换路。无有效绑定正常结束并注明，不补旧单。上例只到PR待审，不触发最终通知或开启自动化。

## 完整交付手动入口

```text
按 HiveFlow 完整交付 HiveOS Issue #N（准确链接），部署到 示例开发环境。
在已明确的目标、风险范围、环境和验收要求内，连续完成开发、测试、
PR、Review及修正、合并、部署、约定验收、必要正式台账更新及同步关闭该Issue和默认原群HTTP回执。
正常范围内不逐步重问；缺少必要上下文或超范围时只停受影响部分并报告。
```

首句简写仅在 [必要上下文](HFL-003-协作流程与授权.md#完整交付简写)明确时成立；示例开发环境从已有受控环境文档核验，不写入机器地址。它不启动定时任务。审阅模式仍用上一例，只到PR待审。

## PR待审后继续合并与部署

PR完成后，Director再介入一次，可以本人操作，也可以在MacMini可信执行会话明确授权继续。以下为合成表达，实际使用须能关联唯一Issue、PR、候选、环境与有效范围：

```text
继续处理这个Issue及已准备的PR（附准确链接）。
在已明确的目标、风险、环境、有效期和验收范围内，完成必要审阅修正、
合并、部署、约定验收、必要正式记录、本单收尾及原来源回执。
先核对原候选和已有检查，复用仍适用的结果；不重新开发已完成部分。
```

这次指令授予核验后的后续范围，PR存在本身不授予合并或部署许可；缺项先核对既有可信上下文，仍缺才最小澄清。完整交付如果一开始已经包含上述范围，则不在PR完成时例行再问一次。

## 定时启动仍选择相同两种终点

定时路径在MacMini本机运行。Director先按[HFL-009](HFL-009-原生自动化任务模板.md)批准配置与实际启用，再由任务在有效范围内选单；PR待审仍等待本人处理后续，完整交付则在授权内连续推进。不能把定时启动写成自动完整交付。

若以后采用“先启用配置，之后在dots只回复采纳”，须先完成 [受控采纳生产/消费核验](HFL-010-采纳记录与任务认领.md)，配置实际启用且范围/环境/时间/数量完整；采纳只作范围内候选条件。首次试验固定一个新Issue，不回放历史。两种[原生模板](HFL-009-原生自动化任务模板.md#两种可复制原生任务模板)默认暂停；实际创建、控制记录和启用状态见[接入与验收记录](HFL-019-接入与验收记录.md#自动开发准备状态)。

## 自然表达与执行依据

对唯一、有效的完整计划，“可以，做吧”可表达同意，不要求复述固定口令；仍须分别核验意图、关联和真实权限。疑问、引述、历史同意和合成示例不产生许可；“继续”只续原授权有效剩余部分，不能开启自动开发或重做交付。

批准快照留在现有审计记录，示例不能代替实际计划。一次批准覆盖列明的范围，实质变化再核对；细则统一见 [核心流程](HFL-003-协作流程与授权.md)。
