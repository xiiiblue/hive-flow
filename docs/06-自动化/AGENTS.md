# HiveFlow目录规则

> 文档状态：Accepted
>
> 责任角色：Director
>
> 本文负责：限定本目录职责，并指向加载、修改和验证规则

本目录与`scripts/hiveflow/`只维护HiveFlow规范和离线辅助工具，不是可部署应用。全仓操作权限、ACDL工程流程及代码规则以根[`AGENTS.md`](https://github.com/xiiiblue/hive-os/blob/4d4f9090aeac6638c424c39d2abbed5ce6183979/AGENTS.md)和[`docs/00-规范/`](https://github.com/xiiiblue/hive-os/blob/4d4f9090aeac6638c424c39d2abbed5ce6183979/docs/00-规范/README.md)为准；本页不增加事前确认条件，也不从文档文字产生执行许可。

## 开始任务

按[HFL-001：规范加载入口](HFL-001-规范加载入口.md)和同版本清单选择路线；先核验本地HiveOS身份、完整HEAD和差异，没有本地项目时才固定远端私有HiveOS版本。不要递归追读全部链接，不读取独立hive-flow作为运行依据。

- 负责人决定与私有结果遵守[两种本人入口](HFL-003-协作流程与授权.md#角色与边界)：dots协调任务使用dots本人主对话，本人直接Codex任务使用可信实际执行会话。群反馈、采纳、旧许可均不等于开工。
- 已明确的完整任务范围连续推进，不重复询问相同步骤；扩大风险、真实工具拒绝或停止要求按根规则处理。默认手动研发，自动开发保持关闭。
- HiveOS Issue的可信来源查询及完成后的原群HTTP回执按[默认收尾](HFL-006-研发交付与原群回执.md#默认交付收尾)处理，不能借通知扩大实施、部署、关单或台账权限。
- 不恢复主动额度查询、余额阈值或流式演示；不增加业务桥接指令、共享锁服务或第二调度器，不宣称原子锁、恰好一次副作用或硬中断。
- 群调查、姓名、登记及单次回执遵守[群反馈规则](HFL-004-群反馈处理规则.md)，未知身份省略，不向群公开内部标识。

## 修改本目录

先检查分支、工作树和既有差异，只修改本次范围。按[HFL-016：文档维护规则](HFL-016-文档维护规则.md)保持单一正文，并同步编号、链接、清单和外部引用，按[HFL-017](HFL-017-安全与隐私规则.md)检查敏感内容。

不擅自修改其他仓库、宿主规则、自动化配置、权限、运行服务、可见性或许可证。新增工具适配要说明真实能力、缺口和验证依据，不能照搬其他宿主的通过结论。

运行`python3 scripts/hiveflow/check_docs.py`及实际受影响的离线测试，再按全仓STD-007完成规定检查。文档检查不等于业务测试或现场联调。修改后是否同步现行任务，按[规范同步规则](HFL-003-协作流程与授权.md#收尾与规范同步)在已有授权内处理，不能只因Git已更新就称配置生效。
