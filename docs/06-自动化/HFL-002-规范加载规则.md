# HFL-002：规范加载规则

> 文档状态：Accepted
>
> 责任角色：Director
>
> 本文负责：固定规范版本、按需读取和自动生成读取证据

## 每次新任务的加载顺序

先核验实际Git根、origin为xiiiblue/hive-os、完整40位HEAD及工作区差异。规范和业务调查使用同一基线；当前明确维护的候选另记差异与内容树。必读规范有未知改动时暂停依赖动作，不覆盖其它会话文件。

本地使用同版本工具一次输出正文和证据：

```sh
python3 -B scripts/hiveflow/spec_loader.py --scenario delivery --receipt /已批准的运行目录/spec.json
```

工具固定HEAD读取，核对所需路径、章节和字节，自动保存完整SHA、文件摘要及结果；不要求Agent另抄一份加载表。实际阅读输出，不能把脚本成功当作理解或实施授权。定时再加`--phase automation`；进入通知阶段加`--phase notify`，接棒加`--phase handoff`。同一会话已读且版本/内容未变时复用，不重复输出长正文。

无本地项目的宿主用已有权限固定私有HiveOS完整SHA，读取同版入口、清单和当前路线/阶段；保存同等必要证据，不必安装本地工具。无法核验身份、版本或完整性时只停依赖部分。

## 加载清单与读取范围

同仓spec-manifest.json是唯一读取映射：common为公共入口，scenarios为intake/review/delivery三条基础路线，phases为到达对应阶段才加载的协议。schema 2增加phases；工具仍能读历史schema 1。`*`表示全文，其它值为标题及子章节。

基础delivery只读根/目录AGENTS和执行主流程；不预读HTTP传输细节、旧PR→dots监听或云端源码缓存。自动选单、通知、接棒按清单附加；旧单槽、旧回执路径和云端快照仅在确实使用时加载。链接是导航，不递归展开。

清单只列同仓根AGENTS或自动化目录Markdown，拒绝未知schema/字段/阶段、绝对路径、`..`、符号链接及动态includes。业务规则和环境文档由根AGENTS与本次阶段按实际需要选择，不将此规范加载清单解释为业务读取禁令。

## 最少加载证据

保留真实仓库、基线SHA、路线/阶段、实际文件/章节及其摘要、读取结果。工具生成的单份receipt即可；本次任务关联、授权及外部结果在原执行记录保存，不再复制审批正文。部署修订另记，不能从规范HEAD推定已部署。

## 失败与重复事件

读取缺失、截断、未知差异或规则冲突时停止依赖动作，保留原因。真实工具拒绝不换账号或通道绕过。版本变化只重读受影响部分；新版本不扩大原请求。事件/事项去重与规范SHA分开，升级不重放旧事件。

## 供现有任务配置使用的提示示例

提示只保留仓库入口、模式和有效参数，使用HFL-009短模板。旧长模板从Git历史追溯，不作为新任务前置流程。

### 群反馈任务

按intake路线读取，只在既有群反馈授权和受众内调查、登记、绑定及答复。若要依赖企微本人身份承接当前请求，必须另行显式读取同一固定SHA的HFL-003“企微本人认证例外”全文并保留读取证据；链接不代替读取，未读全或认证证据不足时停止依赖动作。完成来源核验、规范加载、必要调查和查重并达到建单条件后，直接按已有权限建单，不等负责人采纳；成功且独立读回后，按HFL-004在原群合并回复真实蜂巢Issue编号、简短分析及“待负责人确认”。仅建单受阻、需要额外许可或明显耗时时先给一次有内容的进展，后续成功只补必要状态；采纳等后续决定按原授权简短回执，不重复分析。

### Issue只读扫描与采纳评审任务

按review路线读取，保持只读扫描及单项采纳字段写入的原边界，不从采纳自行派发开发。

### 研发任务入口指引

按delivery路线和HFL-003主流程执行，进入哪个阶段再加载哪个协议；定时入口按HFL-009/HFL-020实际配置。

## 冷启动验证与验收范围

spec_loader.py的固定版本、路径、章节和缓存检查由test_spec_loading.py覆盖；check_docs.py检查本地链接。它们不认证真实人类、不授予GitHub/部署/发群权限，也不证明其它机器具备工具能力。现场结果另记HFL-019。
