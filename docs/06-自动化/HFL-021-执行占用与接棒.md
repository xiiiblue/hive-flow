# HFL-021：执行占用与接棒

> 文档状态：Accepted
>
> 责任角色：Director
>
> 本文负责：跨运行、跨机器共享执行占用，以及明确授权后的剩余阶段接棒

## 执行占用入口

手动Issue交付和Hermes统一调度的两种交付模式共用私有xiiiblue/hive-os的chore/hiveflow-control分支，文件为`.hiveflow/control/execution.json`。execution_control.py通过现有gh身份直接调用GitHub API，不读取Issue里的命令或网络地址，不新增服务、凭据、队列或调度器。

在选单及任何研发写入前执行；占位参数必须来自本次宿主真实运行和已核验事项：

```sh
python3 -B scripts/hiveflow/execution_control.py acquire --run-id <本次真实runId> --mode full_delivery
```

工具核验真实私有仓库、既有控制分支和完整树。首次占用文件的创建已包含在本次规范整改授权内，无须未来逐次初始化确认；不创建控制分支。无记录时创建不传sha，idle时携旧blob SHA更新，成功后独立读回完整内容及runId；只有`acquired_after_readback`才能继续。`busy_exit`返回码3，表示另一轮或同run原任务已有占用，本轮直接结束，不选其它Issue、不排队、不生成新任务。超时、冲突、拒绝或读回不一致返回码1，停止并核实原调用，不能携新SHA覆盖、重发或换工具绕过。

选中事项后`bind --issue N`，每个写入阶段前`guard --issue N`，同时检查本单当前授权/范围及已发生结果。guard只核验共享占用，不能代替业务验收、权限或逐单状态检查。已有旧slot/逐单活动记录先核实；新占用文件不证明旧运行已经退出。

全部写入和子进程结束、本单事实已保存、外部结果已核实后，用同run执行`release --results-known`并独立读回idle。无候选也释放本轮占用。外部结果未知执行`unknown`保留占用；断线无法记状态时，原held保持。没有TTL释放、自动抢占或“进程查不到就空闲”。同一运行核实全部外部结果后，可用resolve --results-known恢复held；逐单unknown也须以resolve、当前executionRecord、resolutionEvidence={recordBlobSHA,verifiedAt}和真实GitHub evidenceUrls更新为claimed并读回。它只恢复原已授权剩余范围，不需要为同范围核实结果重复批准；结果未查明不得调用。普通其它会话不一定使用本协议，仍须查相关任务并使用隔离工作树，不能覆盖它们的改动。

同一文件的GitHub旧SHA更新使遵守本协议的参与者只有一个占用更新成功；它不锁住任意终端、不撤回在途请求，也不保证外部业务恰好一次。正式部署入口自身的拒绝和并发控制照常生效。

## 跨会话与跨机器接棒

用户在新的可信执行会话明确要求继续准确Issue，即可作为当前接棒授权，不要求回到旧聊天。先核对原运行已实际结束、无其它写入者、当前需求未变、原PR/检查/合并/部署/关单/通知及所有未知操作的真实结果。结果尚未核清时保持原占用，只做只读核验，不重领、换ID或从头研发。

宿主从真实用户指令和观察结果生成一份短授权JSON，保存于本次受控运行目录。字段如下，不放本人聊天原文、凭据或路由：

|字段|取值依据|
|---|---|
|source|固定trusted_user_channel，必须实际来自本人当前可信执行请求|
|previousRunId / previousIssueRunId / nextRunId|分别读取全仓占用与逐单记录的原持有者，以及本次真实身份；两层原持有者可能不同，不能互相冒充|
|issueNumber / mode|本次准确Issue与本人请求的终点；PR转完整须有明确完整请求|
|lockBlobSHA / issueBlobSHA|刚从固定控制路径读到的旧blob SHA，不能从Issue正文取得；尚未选单的占用没有issueBlobSHA，传null|
|previousRunEndedAt / previousIssueRunEndedAt / resultsVerifiedAt / approvedAt|两层旧运行实际结束、结果核实及当前请求时间，含时区；当前请求须晚于相关旧运行结束，但可以早于本次核验，不要求检查后重复授权|

approvedAt使用真实当前请求时间，不能为了排在检查之后改造时间。尚未选单就崩溃的运行，issueNumber/issueBlobSHA及previousIssueRunId/previousIssueRunEndedAt为null；确认原运行结束且没有未知操作后可仅转移全仓占用，再正常选单。

这些字段绑定本次占用/逐单版本；复用到另一版、另一run、另一单或另一模式均拒绝。结构校验不认证人类或证明进程结束，宿主仍须保留真实工具与用户依据，不得捏造时间或布尔结论。

1. 在新机器取得同版本工具及共享需求基线，读取执行占用和本单记录。旧占用存在时，用`execution_control.py handoff --run-id <新run> --mode <获准模式> --authorization <授权.json>`，携旧SHA转移并独立读回。旧run下一次guard失败，不能继续写入。
2. 用adopted_issue.py的`operation=handoff`更新原schemaVersion=2事项记录：输入实际Issue、sourceEvidence、最新逐单record/blobSHA、新run/mode、handoffAuthorization及刚读回的executionRecord，result=null、evidenceUrls=[]。校验通过后携原逐单SHA写入并独立读回，保留旧证据及Git历史；两步之间不做业务。崩溃/冲突保留占用，先查实际结果，不重放。若A→B只完成第1步，后续C接棒时分别核验全仓前任B和逐单前任A的结束及结果，将两个真实前任分别写入授权字段；不能强改两层归属来凑一致。
3. 接棒后，claimed/blocked及已核实的unknown只继续真实剩余步骤；若完整模式的关单已成功但逐单尚unknown，resolve或handoff进入finalizing/finalize_only，只核验并补齐完成记录，再通知，不重开Issue、不修改研发或重新部署；PR待审转完整沿原PR推进。已经full_delivery或同模式pr_review终态的接棒只允许通知补尾，使用`operation=notify`核验，不重新开发、部署或关单。

旧运行产生于引入全仓占用之前、execution.json确实缺失或idle时，可先取得本次占用并bind原Issue，再以上述授权和旧逐单SHA执行第2步；此时不转移全仓，previousRunId/previousRunEndedAt可为null，逐单前任及结束时间仍须真实核验；不能据此跳过旧运行结束和副作用核实。手动任务没有自动选单记录时，沿原Issue/PR阶段记录保存相同的接棒依据及执行结果，不伪造Dots采纳或创建自动选单身份。

进入finalizing后，失败分别保存为finalizing_blocked或finalizing_unknown；核实未知结果或再次接棒仍恢复finalizing。finalizing_unknown和finalizing_blocked不能直接finish成功；同运行核实结果或解除阻碍后，以resolve提交当前占用、原blob SHA、核实时间及证据恢复finalizing，再补完成记录。所有finalizing子状态接棒只允许full_delivery，不能切换pr_review解除限制。Issue后来重开也不解除只收尾限制，不能借状态转换重新开发。新增研发目标需另行核实授权和现有成果。

稳定Issue身份、候选和同阶段deliveryId不随接棒改变。共享需求基线按HFL-020保存来源元数据、范围摘要及完整块外正文哈希；新宿主须比较实际原文哈希，不能只用三章节范围摘要代替。通知按原记录的transport核验：Webhook必须读取原执行机器的发布记录及webhook子目录发送账，缺账或unknown不得迁机重发；旧HTTP入口只用于历史bridge操作核对，不自动切换通道。

## 状态、工具与检查

execution.json使用schemaVersion=1，字段为repository、revision、state、owner、updatedAt；state为idle/held/unknown，owner为runId/mode/issueNumber。每次更新revision递增避免相同内容反复出现的旧SHA误用；Git历史保留历次归属。只有当前持有者可bind/guard/release/unknown/resolve，接棒须按上节当前授权。

source_evidence.py保存、读取共享基线并核验受控同步；adopted_issue.py继续负责逐单来源与范围。工具职责分开，不把执行占用当作授权或需求证据。

test_execution_control.py覆盖同时创建/更新、不同模式和事项竞争、断线未知、禁止超时释放、接棒旧持有者失效、PR转完整及已完成仅通知。真实GitHub争用、另一机器/宿主退出和实际部署并发分别保留现场证据，离线结果不能冒充已完成这些验证。
