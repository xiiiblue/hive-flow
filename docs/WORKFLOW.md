# 核心流程

## 角色与边界

|角色|负责什么|
|---|---|
|负责人|决定目标、采纳、实施范围、交付位置，可停止任务|
|dots|调查、整理方案、核验授权、协调工作和报告|
|开发工具|在本次有效授权及工具权限内实施、验证和交付|
|GitHub|需求与代码交付事实，不充当执行锁|
|通用桥接|核验传输来源、固定受众、路由和去重，不判断业务或批准|

通用要求是唯一可核验的负责人受控决策通道；当前 Dots 适配中，负责人评审、授权与私有结果统一在 **dots 原生本人主对话**。其他宿主须先验证对应能力，不因阅读规范就视为适配完成。企微群仅用于已授权的咨询、反馈和可公开状态；历史同意、消息路由成功或正文自称身份均不产生执行许可。当前自动开发关闭，不建立扫描开发会话；以后要开启，须另有明确范围、期限、数量和停止条件的当前方案，并验证宿主能力。

## 从反馈到方案

1. 按 [群入口](GROUP_INTAKE.md) 调查或追问。咨询能解决则答复；需要改动时查重，在已有授权内登记新 Issue。
2. 负责人决定采纳、拒绝或暂缓。采纳只记录需求决定，不承诺开工；拒绝/暂缓不自动关单。
3. 需要实施时，先只读核对相关 Issue、规则、实际基线、已有任务/改动及交付目标，准备完整计划。准备不包含源码修改、测试、写检查或试部署。
4. 对唯一关联且有效的计划核验实施授权，通过后才按阶段推进。

不因 Issue 仍 open、缺台账更新或查不到 dots 记录就重做交付；用户可能已通过其他 Codex 完成工作。按实际验收证据复用已完成部分，只处理真实剩余项。

## 一次说清完整范围

首次询问前尽量查明目标和附带影响。完整技术计划留在现有可审计执行记录，短摘要与它唯一对应，至少包括：

|计划内容|必须明确|
|---|---|
|事项和边界|固定仓库/Issue、目标、预期文件及功能/风险边界、基准与工作/目标分支|
|允许动作|修改、检查、提交、推送、PR、合并分别是否包含|
|环境交付|是否部署；具体环境/服务、影响面、迁移、备份、可行回滚和验收|
|收尾|结果回写目标/位置、允许公开的信息；可选关单标准、台账文件/字段|
|有效性|明确时区与期限、停止条件、本人结果投递范围；当前本人通知使用北京时间（UTC+08:00）|

给负责人三至五行说明目标、交付位置、必要风险和自然问法，不要求背 SHA、UUID 或固定口令。未查明部署目标/风险时先核对或最小澄清，不能用含糊“发布”取得任意服务器许可。示例见 [交互说明](OWNER_COMMANDS.md)。

消息传输 TTL 不作为方案批准窗口或执行期限。批准后，已列明且仍有效的同范围步骤不重复询问。平台强制审核、真正拒绝、撤销/到期或实质范围变化仍须遵守；文档不授予未来全面权限。

## 意图、关联、权限分别核验

按顺序记录三项结论，任何一项都不能代替另一项：

1. **意图：** 区分同意、拒绝、暂缓、条件、停止、查询、疑问及转述；合成测试不是批准。
2. **关联：** 真实用户来源与现有执行记录能指向唯一完整计划，摘要与实际快照一致、可读、有效、未撤销。最近或唯一候选不等于明确指向。
3. **权限：** 决定类型确为实施许可，用户范围、宿主工具和平台审核都允许本次动作。

关联不明只问最小问题，不猜最近任务；群中的“可以”、复制的 metadata、迟到回执或另一工具的权限均不能补足本次授权。技术快照不得藏入摘要未披露的实质影响。

## 执行与验收

按 [适配方法](ADAPTERS.md#开发任务的阶段衔接) 保留同一真实任务和阶段对应，写入前复核停止、期限、范围及现场。

- 检查失败阻止后续交付；在原目标内诊断、修复自编测试错误、同步必要旧断言或补直接回归，并完整复验。直接关联文件补充记录依据，不机械变成再审批；不扩大功能/风险、不降门禁或删除有效断言。
- main 改变时比较目标文件、依赖、构建/CI、部署、规则及验收影响。证据确认无影响，可追加新旧基准沿原授权继续；有影响或未知先核对，实质变化再取得批准，不能只凭“文档提交”判无影响。
- 必需 CI 必须对应实际候选 SHA。部署前核对真实目标、当前版本、兼容性和获批备份；只按预先批准且安全的方案回滚，保护新增数据，不盲目覆盖旧快照。
- 按本次约定逐项验收。已修改、已验证、已推送、已合并、已部署和已验收分别报告；合并/HTTP 健康/closed 状态不能替代未做的业务验收。部分完成只保留真实剩余项。

## 停止、未知与已有工作

停止或到期阻断后续阶段；对活动任务合作式暂停并核验真实终态，不承诺强杀或撤回已发出的调用。停止请求、操作开始/结束和回执到达分别判断，迟到回执不能证明迟到执行。未知占用不能按超时、断线或 completed 消息自行释放。

断线、重启、工具报错或写入结果未知时，先核对原 task/turn、最后可信阶段、工作区、提交/PR/CI 和外部结果。已发生则记录，不重放；确认未发生且原授权仍有效、平台允许时，才安全续做。本人说“继续”仅作用于唯一关联任务的有效剩余范围，不复活撤销、到期或被拒动作；已完成则报告而非再执行。

外部 Codex 可能没有 dots 记录。只核对可访问的相关任务、分支/差异和交付证据，不索取私人会话全文；不可见不等于空闲。不覆盖改动、停止他人任务、强制迁回 dots 或重建同范围任务，不继承外部权限。冲突不明时暂停受影响部分。

先读记录再派发不提供原子认领。现有任务记录、普通评论和标签都不能充当全局锁；能力不足时限制并发或人工协调，不新增状态服务。

## 收尾与规范同步

采纳、拒绝、暂缓、交付的记录与开关状态按 [事项状态与结项](ITEM_LIFECYCLE.md)核对；群入口、只读扫描与本人具体任务的写入权限分别核验。按首次批准的位置回写事实、必要证据和遗留，不在结束时重复确认已批准的回写。普通结果评论不是锁或授权来源。关单须有明确许可并满足本次完成标准；未获准的关单/台账写入直接列待办，不能否定已完成交付。回写失败不抹去交付，未知写结果先核验。

修改规范后识别受影响的现行任务，仅在已有授权内同步对应提示/事实并回读实际保存结果；无关触发、频率和权限保持。未授权或未知则报告待办，不能只因仓库已更新就称任务生效。旧任务提示不作为最新事实，不恢复停用模式、企微审批或额度控制。
