# 从桥接器提取 HiveFlow：安全迁移计划

**本文是计划，不执行迁移。** 不打开或修改生产数据库，不推送仓库，不发布、不部署。仅复制休眠控制代码不能完成 Issue 状态迁移。

## 目标与不可破坏的约束

HiveFlow 最终拥有 Issue 提案/决定、不可变身份与修订、执行授权、模式、额度门槛和认领；桥接器保留通用认证、路由、发件箱和传输去重。现阶段生产桥接器必须保留全部持久 Issue 记录和旧路径，直到完成验证与受控切换。

原系统已将 Issue 审计记录与短期投递任务区分：`issue_proposals`、`issue_decisions` 和 `kind='issue'` 的请求不因普通请求 TTL 被删除；发件箱 `jobs` 仍可按自身有效期清理。迁移不可把审计记录错误地纳入短期清理，也不可把已过期消息一律重发。

## 必须纳入清点的关联

- `issue_proposals`：原提案/review ID、request ID、仓库、不可变 Issue ID、编号、revision、原始 snapshot、owner/channel/root、创建时间和状态。
- `issue_decisions`：proposal ID、决定、理由、actor、唯一来源 source、时间。保留 `decision_record_only` 语义，不生成执行许可。
- 关联 `requests`：包括 ID、source、target、时间、有效期、root、status、kind、owner、channel。
- 关联 `jobs`：原 job ID、request、方向、原 payload、状态、lane、target、有效期及外部投递证据。
- `seen` 等入站去重证据及相关评审关联：识别它们与 Issue 路径的依赖，不能只导出两张业务表。通用传输记录可继续由桥接器保管，但必须保存稳定交叉引用和消费责任。
- 独立 `workflow.sqlite` 如有真实数据，单独清点控制状态、授权、认领及恢复要求；不得假设现有控制库为空，也不得因复制代码覆盖它。

实际 ID、用户、频道、主机、凭据及生产快照不得写入项目文档或测试夹具。导出物只能留在已授权的受控位置；复制到其他服务或仓库前另行核验授权与访问范围。

## 分阶段门槛

### 1. 固化契约，生产不变

保留旧实现和数据库。定义 HiveFlow 业务接口与桥接器传输接口，明确认证上下文、业务去重键、传输关联键和错误行为。不可让两边同时独立接受同一决定或重建待发送任务。新控制代码默认休眠；不接线上入口。

### 2. 离线导出/导入验证

先实现版本化格式与可重复运行的导入器，在合成数据及获准的隔离副本上验证。生产导出须使用一致的 SQLite 备份/快照机制，考虑 WAL；不能随手复制正在写入的单个数据库文件。

导出需记录格式/模式版本、快照边界、行数、校验值和稳定主键，保留历史状态与原始关联。导入应事务化、幂等，遇到同 ID 不同内容或不完整关联须失败并报告，不能静默覆盖、重新编号或补造批准。重跑不得新增消息、决定或授权。

核对每个仓库的 ID/编号双向映射、各修订内容、pending/superseded/decided 状态、所有决定及唯一来源、每个待处理批准的可回复入口和每个发件箱任务的唯一责任方。不能仅比较总行数。

### 3. 授权后进行单写者切换

预先确定短暂停写/缓冲边界、负责人、回退条件和用户反馈方式。在获得切换授权前不执行。切换时冻结旧业务写入或通过经验证的唯一入口路由，保存最终一致快照并完成增量对账；始终只有一个权威业务写者和一个负责该任务的投递者。

旧的 review/request/root/source 标识保持可解析，切换前已发出的评审请求仍能落到原提案和版本。已经决定的提案不得再次决定；待处理且可用的批准不得丢失。已 superseded 或已决定的请求不得因为迁移重开。保留已失效投递的审计记录，是否重新请求评审须显式处理，不能恢复旧 TTL 后盲发。

当前桥接器启动时把 `sending` 转为 `unknown`。对此类“可能已经发出”的消息，先核验外部接收证据，不能直接改为 pending 重试。发件箱去重本身不保证外部 exactly-once；必须通过稳定幂等键、可靠回执或人工核对证明没有重复后再推进。不能证明投递结果时保持隔离并阻止相关重放。

通过检查后才转移 Issue 业务入口。通用桥接器继续负责其发件箱；跨业务/传输边界的提交与重试契约必须经故障测试证明不会重复或漏发。不要把迁移当作启用执行授权、自动模式或部署的机会。

### 4. 验收、观察与回退

切换验收至少覆盖：重复入站、旧修订、同版本冲突、defer 后新修订、跨切换待处理评审回复、重复决定来源、过期消息、pending/sending/unknown/sent 任务、写入中断和重启。断言无重复外部消息、无重复决定、无遗失待处理批准，且所有旧记录型批准仍不可执行。

回退须先停止新写者，核对新系统已接受的决定与投递结果，把切换后的必要增量以幂等方式对账回旧路径。不能简单恢复旧快照后重放发件箱，否则可能丢失新决定或重复发消息。无法证明一致时停止切换并人工核验，不能以重试掩盖不确定性。

验收证据与观察窗口由负责人明确，不能用任意等待时长替代一致性证明。旧审计数据及备份继续保留；任何删除、清理或旧路径退役都另行计划并取得所需授权，不在本次范围。

## 本次交付边界

本次仅提供项目骨架、工作流边界与迁移计划，另由代码提取任务提供休眠模块及其单元测试。未实现导出器、导入器、跨系统切换或端到端验收；未触碰生产记录，未宣称零重复迁移已经完成。
