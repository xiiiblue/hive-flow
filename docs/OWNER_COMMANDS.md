# 本人交互与简洁中文通知

由智能体理解研发意图，不要求用户记忆桥接业务命令或 UUID。以下是沟通示例，不宣称当前线上已有原生解析，也不授权规范之外的操作。实际账户、来源和工具权限须先核验。

## 当前渠道：只在 dots 本人主对话审批

所有需要本人询问、评审、取舍或授权的事项，以及本人审议后的结果回传，统一留在 **dots 原生本人主对话**。智能体在这里给短摘要、接受自然确认并关联完整计划；不再向企微发审批，也不让本人在两处重复确认。转发到执行子任务时必须携带可核验的本次 dots 授权依据，子任务不能自称代本人批准。

企微群仍可收集反馈、普通咨询并接收建单回执；群只得到适宜公开且在原授权范围内的业务状态，不公开本人审批内容或私有执行细节。需要本人决定时转由智能体在 dots 询问；企微普通私聊不成为批准入口。

此前企微审批路径**暂不启用**，历史审批不重放、不转成 dots 新授权；#84 已另获授权部署 51.8 并完成有限技术验收，Issue 仍 open，自动开发关闭。未来 Hermes 仅保留待适配方向，不能直接接管或继承已通过的审批。

群入口先调查并动态区分咨询、Bug 和需求，必要追问、查重后答疑或新建可读 Issue，详见 [群入口](WORKFLOW.md#群入口先调查再答疑或建单)。新需求/缺陷及评审通知除项目名、事项和编号外还附 Issue 链接，简述调查结论与待决定项；咨询已解决不建单，采纳不等于执行批准。群仅收到相关可公开结论和链接，私有审议与执行批准留在 dots。

## 群答复与登记回执

群里先说结论或已确认状态，再给最少解释；不复述整段提问，不另发与桥接重复的收到回执。追问每次 1–2 个关键问题，已提供的信息不重问。需要区分事项时写“关于你提到的登录页标题”，不暴露内部 ID，不伪装 @；未经验证不能说已提醒到某人。传统桥接短回执为“收到，稍等”，保留最终普通回复方式。

新单写入实际核验成功后，群回执示例为“已登记为蜂巢 #42：登录页标题显示不准确，待负责人评估”，可附原授权内允许公开的 Issue 链接。这一句即可，属于登记事实，不表示已采纳、开工或获得执行批准；失败或结果未知不得先报成功。此处 #42 为合成示例，不创建真实事项。本人通知仍按下文保留项目名、事件类型、事项和三至五行摘要。

## 手动推进：短说明与自然批准

本人通知首行或开头写项目名、事件类型、Issue 编号及必要短事项，例如“蜂巢｜需求评审 #42：登录页标题”。新需求、评审、进度和结果均如此，避免只写 #编号；未建单写明未建单，不编造编号。每条保持三至五行清晰短中文，不堆机器字段。方案说明目标、交付位置、必要风险及一句自然问法，例如：

```text
蜂巢｜执行方案 #42：调整登录页标题，让产品名称显示正确。
测试通过后提交推送、开 PR 并合并，发布到本次核实的 51.8 员工端。
先备份，失败按已核实的安全方案回滚；影响仅限标题展示。
完成后回写这项 Issue 的结果；不自动关单或改台账，同范围修复重试不重复询问。
可以按这个完整范围做吗？
```

以上为未来单任务的表达示例，不是实际方案或对未来任务的全面授权，51.8 也不是默认发布目标；未经核实不能承诺部署环境、影响范围或回滚可行。一次事先说清并获批准的方案可覆盖修改、测试、提交、推送、PR、合并、明确目标部署和验收，中途不对同范围动作重复询问。不能默认批准任意服务器发布。完整计划同时列明结果回写位置、可选关单标准和台账写入范围；缺授权的收尾直接列待办，不为小事追加确认。

完整技术快照仍保存在现有、可审计的执行记录：固定仓库/Issue、目标、预期文件及功能/风险边界、基准、分支、逐项动作、部署目标、检查/验收/备份/回滚、执行期限及本人结果投递。短说明必须在现有审计对应中引用唯一完整计划记录，批准前实际读取并核对二者一致；引用缺失、多候选或摘要未披露实质影响时不能实施。此引用由宿主管理，不要求本人阅读或复述 SHA、文件清单、版本号、UUID。准备方案只读，不改源码/分支、不执行写检查。预期文件清单不是机械审批门槛，直接关联测试补充及原范围修复按 [修复边界](ADAPTERS.md#测试修复与文件范围) 留痕复验；不扩大功能、风险、数据或环境。

对一项有效且唯一关联的明确方案，可信本人说“可以，做吧”即可表达批准意图，不要求固定业务口令。仍须核验实际本人、可信来源、方案关联及有效状态；寒暄、转述、历史同意、其他话题和合成测试均不是许可。dots 主对话内新话题无法可靠关联时，只问最小问题，例如“你说的是登录页标题这项吗？”，不能猜最近任务。平台权限审核未通过时，即使意思明确也不能执行。

只有授权范围实质变化才重新批准。无关 main 文档更新经核实不影响目标文件、依赖、构建/CI、部署脚本、研发规则和验收后，可在执行记录追加新旧基准及判断依据后继续；有影响或未知则先停止核对，不自动扩权。具体规则见 [手动适配](ADAPTERS.md#dots-云端手动执行适配)。

如果本人已直接在其他 Codex 处理，先核对可见任务/改动与真实交付，不猜空闲、不覆盖；已验证的结果尽量复用，具体见 [外部工作衔接](ADAPTERS.md#用户直接使用-codex-时的衔接)。

“查询这项进度”只报告现场；“先停下”须可靠关联受影响任务并合作式停止，核验真实终态。本人结果继续回到 dots 主对话；上下文不可用时先恢复可信任务对应，不转往企微补审批，也不重获开发许可。

**当前限制：** 此前平台权限审核拒绝从企微桥接批准恢复 #84 v3；历史拒绝不因渠道文档更新而撤销。改用 dots 主对话是本人询问方式的变更，不是执行 #84 的授权，后来 dots 分别批准了修改测试合并和后续部署；已做有限技术验收，仍不代表完整真实业务验收。

## 自然表达的验收入口

同意、拒绝、暂缓、停止、查询、条件同意、疑问/转述的统一预期及反例集中维护在 [验收用例](ACCEPTANCE.md#用例与必须观察到的结果)，不在本页另设口令或重复语义表。意图识别、方案关联和权限逐项核验；已有 dots 分阶段修改测试合并与后续授权部署实例；反例矩阵、真实账户和恢复演练未全验，企微审批仍未启用。

## 自动模式（当前关闭）

先准备独立会话方案 A1，列明仓库、选择规则、文件范围/动作/环境、东八区起止与截止、扫描频率、任务数量、停止、验收和回滚。本人在有效且唯一关联的会话方案中明确表示开启（例如“按这份方案开启自动推进”），且实际平台能力已验证后，才可创建会话专用云端定时任务。本轮不创建或开启。

会话内自行扫描范围内已采纳事项、形成计划并推进，不要求逐项手工入队；越界或结果未知即停。历史事项须由新会话明确覆盖，旧 record-only 不默默升级。可靠关联的“停止自动”或到期只停对应自动扫描及后续阶段，不影响正常问答与 Issue 评审；活动任务仍核验真实终态。细则见 [自动模式](AUTO_MODE.md)。

## 通知模板

以下 #42 和事项均为合成示例；“是否采纳”只问需求评审，执行须另有关联明确的有效方案批准。

```text
蜂巢｜新需求 #42：登录页标题显示不准确。
建议：调整为产品名称，影响仅限标题展示。
请您评审是否采纳；本条不请求执行批准。
```

```text
蜂巢｜评审结果 #42：登录页标题问题已采纳。
状态：仅记录需求决定，尚未启动开发。
下一步：准备实施方案，取得执行批准后推进。
```

```text
蜂巢｜进度 #42：登录页标题调整已完成，正在运行必要测试。
状态：尚未提交，未部署。
下一步：测试通过后按已批准方案交付。
```

```text
蜂巢｜交付结果 #42：登录页标题调整已测试、合并并部署到获批开发环境。
验证：页面与健康检查通过。
遗留：用户端验收待确认。
```

```text
蜂巢｜执行受阻 #42：登录页标题任务遇到平台额度耗尽。
现场：已记录当前进度，未盲重试，未重复派发。
下一步：核对原任务与外部结果，按实际平台可用性和有效授权恢复。
```

模板只示意表达，不是本次真实结果；#84 当前应报告“已修改/验证/推送/合并/部署 51.8，有限技术验收通过；真实账户及恢复演练待办，Issue 仍 open”，不能写成全部业务验收通过。清楚区分“已请求停止”“实际已停止”，以及“已发送”“接口确认”“用户已看到”。不默认展示 UUID、凭据、原始正文、堆叠日志或一大段协议字段；需要恢复关联时提供最小编号和详情入口。

## 通用桥接保留，企微审批暂不启用

独立 bridge 的 `[wecom:notify]`、短编号回复和 `[wecom:owner]` 通用能力继续保留，用于获准的普通消息传输；本轮不删功能、不改配置或部署。短编号只关联通用会话，不是当前本人授权入口，HiveFlow 不要求用户用它完成审批。

通用传输 TTL 仍是 3600 秒、不续期，东八区简洁显示；这些规则不适用于 dots 主对话的批准受理窗口，更不代替计划执行期限。既有传输实测仅证明通道，不证明企微授权可用。过去事实见 [记录](MIGRATION.md)，历史协议见 [存档](LEGACY_APPLICATION.md)。
