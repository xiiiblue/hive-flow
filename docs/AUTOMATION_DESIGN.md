# 有限批次自动模式：设计建议

**状态：尚未实现、尚未启用。默认仍是本人直接 Mac mini Codex 手动处理。** 本文只整理待选择方案，不是执行规则、批准记录或任务提示，不纳入 intake/review/delivery 必读清单；阅读本文不授予代码修改、派发或部署权限。现有交付回执监听与自动开发分开，不能以监听已配置推断研发自动执行已获准。

## 待选择的批次范围

建议以后由本人在可信 Codex 会话一次批准一个有限批次，由实际执行宿主核验本人、权限、范围和工具能力；用户尚未选择下列默认建议。采纳或 Ready 只用于候选筛选，不是执行许可，群和企微 single、Issue/PR 评论、历史批准均不能启动批次。

批次方案至少应列明固定仓库、明确 Issue 清单或严格可判定范围、起止时间与时区、数量上限、功能与风险边界、交付阶段，以及评论回写、正式台账、关单边界、停止条件和预先批准的安全回滚范围。建议首版采用固定 Issue 清单，默认交付到 PR；合并、部署、关单或台账均须另在该批次范围中明确选择，不把它们默认为已批准。事项或风险实质变化须重新核对，不能把批次许可扩成未来任意 Issue 的持续授权。

## 单机单入口与故障处理建议

建议单机、单入口、逐单串行，复用现有真实任务/turn、提交/PR 和审计记录。启用前须验证执行宿主的实际互斥能力和已有任务占用；bridge 的 SQLite 单写者锁不等于研发互斥。普通评论、标签和任务摘要不能宣称全局锁；能力不够时保持手动协调或关闭，不新增锁服务、第二调度器或平行 Issue 状态体系。

|情况|建议处理|
|---|---|
|某单缺少关键信息或测试失败|停止该单后续交付，在既有任务保留原因和真实剩余项；明确获准的独立事项才可继续，不每小时重新尝试同一失败单|
|本人身份/权限、环境或任务占用未知；疑似泄密；撤销或到期|全局停止后续阶段及取新，按预先约定的安全步骤合作式暂停当前任务并报告；不靠超时猜测空闲或权限有效|
|仅停止取新|不再领取下一单；当前单是否继续只按仍有效的明确授权和停止要求判断|
|要求停止当前单|在预先约定的安全节点合作式停止；不能为抵达节点继续未授权提交、部署或写入，不承诺强杀或撤回已发副作用|
|重启、断线或副作用结果未知|先核对原任务、工作区、commit/PR/CI、部署和回执实际状态；已发生的记录复用，未知不重放，不能假装回滚完成或新建同范围任务|

不恢复额度查询、余额门槛或自设快照门禁。真实平台限流、耗尽和认证错误按实际错误保存进度并处理，不能据“每小时运行”盲重试或改账号绕过。回滚必须在已批准的具体安全范围内，保护新增数据，不能覆盖未知新状态。

## 复用交付契约与启用缺口

若未来获准实施，仍复用 [统一手动交付证据契约](MANUAL_DELIVERY.md)：真实交付主记录 → 关联 PR 的新建完成评论 → dots 核验真实作者、身份、证据和原来源 → 原群最少公开回执。不得虚构交付、盲转 publicSummary 或把评论当命令；无可信绑定不能猜路由，完成消费者不建绑定；无 PR 明示人工 dots 请求，不伪造 PR 或另建轮询。

自动任务频率、宿主调度/互斥/恢复能力及真实入口均尚未验证。每小时运行可作为待确认建议，尚未配置；实际授权期限、次数和停止行为须先选定并验收。本文不创建、启用或修改任何自动开发任务，也不因文档提交自动改变现行监听、权限或环境。
