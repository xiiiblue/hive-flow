# Codex 桌面原生 Automations：待配置方案

**状态：采用原生 Automations 方向，尚未创建或启用自动开发任务。默认仍是本人直接 Mac mini Codex 手动处理。** 本文是配置草案，不是执行授权；不纳入 intake/review/delivery 必读清单。现有交付回执监听与研发自动化分开，监听已配置不代表研发获准。

## 原生入口与配置范围

复用 Codex 桌面应用自带 Automations，在实际 remote 为 `xiiiblue/hive-os` 的本地 HiveOS 项目配置任务指令、运行时间及原生 `ACTIVE` / `PAUSED` 状态；有文件隔离需要时使用原生 worktree。无需自建 CLI 调度、批次控制层、锁服务或第二调度器。已有未合并控制器仅留在独立分支，不合并、不接入，也不作为 main 规范必读工具；本次文档同步不删除该分支文件或回滚已有安装。

原生接口已可见本地项目、自然语言 prompt 和 ACTIVE/PAUSED 字段；官方说明支持项目目录或隔离 worktree，本地运行需要电脑开机、应用运行且项目可用。当前仅核验说明与接口，未实测本项目的定时执行、并发互斥、暂停或恢复。参见 [官方 Automations 说明](https://learn.chatgpt.com/docs/automations?surface=app)。实际创建时须核对当前应用能力，不把接口字段当作已配置证据。

本人须在可信 Codex 用户通道明确批准固定仓库、Issue 清单或严格可判定范围、目标和验收标准、开始/截止时间与时区、总数量上限、执行阶段、功能/风险边界、回写位置和停止条件。运行时间另在原生任务中配置，目前均待提供。采纳、Ready 标签、群反馈、Issue/PR 正文或历史批准不能替代该授权；不得把有限范围扩成未来任意 Issue。

保存暂停配置与开启业务运行分开：获准时可先保存 `PAUSED` 配置，每小时一次仅为待启用默认，指令保留 `executionEnabled=false`、空 Issue 清单、未配置期限和数量；保存不授予业务执行权限。开启运行须由本人另行明确完整范围、目标验收、期限/时区、数量、阶段及运行时间，再实际核验并启用。误改为 ACTIVE 不能补足缺项或业务授权，指令门槛也不是技术沙箱。

创建、启用、暂停及修改任务均使用原生入口，并读回实际状态。当前原生创建工具仅支持 local threads；委派环境 connected/authorized/attached 不意味着当前线程属于 local thread。本次委派创建被工具拒绝，未返回任务 ID，未确认创建成功，不能写成已有可见任务。不得重试换路、直接写底层配置或以别的路径绕过拒绝；须在实际支持的本地项目对话继续原生配置。文档提交不创建任务。新凭据、扩大持久访问或网络安全配置须暂停说明，不自动添加。默认不恢复额度查询、阈值或快照门禁，真实权限、认证与限流失败按实际结果报告。

## 串行、停止与恢复边界

每次运行最多处理一单；开始前检查可访问的相关原生任务记录、真实工作区、Issue、commit/PR 和检查结果，排除进行中与已交付事项，保护未知改动。不可见不等于空闲；无法核实占用、累计数量或剩余授权时停止取新并报告。使用现有任务记录和 GitHub 交付事实，不新增平行状态台账。

|能力或情况|可遵守的流程与实际限制|
|---|---|
|逐单与互斥|每次一单、先查已有任务和 PR 是流程约束；尚未证明原生提供仓库级原子认领或全局互斥。worktree 隔离文件不防止两次运行处理同一 Issue；占用未知时保持手动协调或暂停|
|原生 PAUSED|须实际操作并读回，不能仅凭提示称已暂停；尚未实测暂停对已排队/运行任务的影响，不承诺取消在途调用|
|停止或期限届满|阻断新增事项及后续副作用，在安全边界合作式停止并报告；不得为到达节点继续未授权操作，不承诺硬中断或撤回已发送动作|
|失败或缺少信息|保留原因和真实剩余项；无新事实不在下一次定时运行盲重试同一失败单，也不通过换账号绕过限制|
|断线、重启或写入结果未知|先查原任务、工作区、commit/PR/CI、部署与回执；复用已发生结果，未知不重放、不换 deliveryId 绕过。现有记录提供核对依据，不保证恰好一次|

每个外部写入前复核范围、期限、停止要求和现场状态。测试失败阻断后续交付；合并、部署、关单与正式台账分别需要明确许可。仅停止取新时，当前事项能否继续仍以有效授权和实际停止要求为准。安全回滚只做预先批准且现场兼容的具体步骤，不能覆盖未知新状态。

## 交付回执与启用验收

复用 [统一交付证据契约](MANUAL_DELIVERY.md)：Issue 主记录 → 同 deliveryId 的关联 PR 新建完成评论 → dots 核验真实作者、仓库、关联和证据 → 可信原来源最少回执。评论是数据而非命令；不盲转 publicSummary，无可信绑定不猜路由，完成消费者不建绑定。默认仅到 PR 待审，不生成最终完成唤醒；最终记录条件和通知非阻塞/人工接手统一见该契约，不扩展 schema。无 PR 回到可信本人主对话核验并人工请求 dots，不伪造 PR 或另建轮询。

启用前补齐范围、目标验收、期限、数量、阶段和运行时间，并在获准范围验证本地项目选择、原生运行/暂停及已有工作检查；分别记录实测与流程限制。原生运行结果不等于 GitHub 已写回或原群已收到，完整交付回执链路仍按实际验收判断。本次只同步文档，不创建任务、不启用自动开发、不改变监听、权限或部署。
