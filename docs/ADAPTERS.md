# 智能体与工具适配说明

HiveFlow 是流程规范。适配是把责任映射到**已经存在且已获授权**的工具，不是开发一个新的 HiveFlow 业务服务。规范和适配表本身都不能授予权限；平台限制与实际能力优先。

## dots：已有能力与仍须核验的连接

依据本次协作已验证的能力，可采用以下分工；不意味着每个账户或未来宿主都具有同样能力：

|责任|dots 已验证可用的工具类别|接入前核验|
|---|---|---|
|定时唤起、截止关闭、事件响应|自身云端定时/事件任务|当前账户可用类型、最小间隔、截止/暂停效果和重复唤醒|
|Issue 上下文与交付证据|已连接 GitHub 工具|固定仓库、真实作者、main SHA、PR/CI 事实；不新增评论/标签充当锁或正式执行台账|
|消息接收和线程回报|已连接 Slack 工具|工作区、私有频道、实际 App 作者、桥接来源与线程身份|
|具体开发任务与回报|当前环境提供的 cloud_threads 等任务工具|目标环境、任务创建权限、确切任务身份、状态读取、中断和结果证据|

定时任务先读取明确有期限的会话授权，扫描范围内已同意事项并协调单任务占用，不让用户逐个手工入队。事件和评论是唤醒线索，必须重新核对当前授权、版本、状态及去重，不能仅凭控制文本创建开发任务。

工具名可按宿主映射；不把一个宿主的内部调用写成所有 dots 的永久公共 API。现有扫描/反馈任务已经替换为通用通知/回复协议，保留原触发和频率；手动控制分支已配置，这不证明实际预检、额度检查和开发全链路已验收。真实研发尚未执行，自动开发关闭，#84 暂缓。本轮仅发布文档。

## dots 云端手动执行适配（规范，尚未真实执行）

云端手动控制分支已按以下流程配置；真实研发尚未执行和验收，不将配置完成说成全链路已通过。

### 只读准备不可变方案

本人说“准备 #N 的执行方案”只允许读取固定仓库的 Issue、现有 comments、main SHA、AGENTS 和最少必要源码，不改源码/分支、不运行会写文件或状态的检查、不启动实际研发。#84 继续暂缓。云端方案须明确：

- 问题、目标和 Issue 身份；精确允许文件、基准 SHA、工作分支与目标分支。
- 逐项允许动作，包括是否允许修改、检查、提交、推送、PR、合并及部署；不包含的动作不得默认为允许。
- 指定部署环境/服务、检查、验收、备份及安全回滚条件；未允许部署时明确不部署。
- 执行期限（东八区明确时间）、停止条件，以及本人结果投递范围。

一条新的通用通知承载一份完整、不可变的 `#N vV` 方案，并明确请本人回复“执行 #N vV”。bridge 只接收 `{text}` 正文并生成短编号；例如本人发送 `回复 N1 执行 #42 v1`。方案变化使用新版本及新通知根，旧版本标为已替代，不覆盖已批准快照，也不把一个会话中的后续正文当作方案修订。通知 TTL 3600 秒是批准回复的受理窗口，**不是执行截止**；执行期限由方案单独写明。

### 验证批准、去重与唯一对应

按真实平台记录同时核对：发起根来自固定 Ditto bot，回传来自固定 bridge App，频道固定，来源为已认证本人 single，回复属于该根唯一方案版本，正文精确为“执行 #N vV”，方案未停止、撤销、过期或被替代。新通知根与完整方案、后续真实任务/turn 及回执的对应保存在现有云端会话证据中；无法核验就停止，不新造业务状态服务。仅靠正文/metadata 自称、显示名或一段引用不能满足核验。

普通“同意/OK”、旧 record-only、旧业务根或旧精确命令均不是这条新授权路径。对应根缺失、内容不完整、多个版本歧义时不猜。重复触发先查该来源和版本已有回执，以及真实 `cloud_threads` thread/turn；不能凭标题认任务，不能因查询未知、重启或通知过期盲目重建。当前创建接口没有客户端幂等键；读历史再创建并不提供原子认领。

### 一个 medium 子任务：先预检，再按阶段继续

只有上述批准验证通过后，使用用户已连接的 **Mac mini**，以 **medium** 创建一个子任务，首轮仅做只读预检：核验实际基线、脏工作区、活动任务和工具，不改源码/分支、不执行会写状态的检查。保留现有工作，不清理、重置或覆盖无关修改；现场不符或占用不清就暂停。该段是适配规范，本轮没有创建任务。

额度必须通过该 Mac 上 bundled Codex app-server 的 `account/rateLimits/read` 读取**当前真实账户的全部适用窗口**，保留观测时刻和来源。逐窗计算剩余；来源不清、缺失/未知、不新鲜或任一窗口剩余 ≤5% 时停止。旧读数、GitHub API rate limit、最高余额窗口或推测值不能替代。读数不代表额度预留，不自动购买/重置额度。预检失败只能报告，不能启动修改。

预检通过后，在**同一 thread** 按已批准方案分阶段继续；记录实际 turn、候选/交付 SHA 和结果，不为每个阶段另建重复任务：

|阶段|写入前门槛|完成证据|
|---|---|---|
|修改与测试|再查当前额度、停止/撤销、期限、允许文件和占用|实际差异、检查结果及对应候选 SHA|
|提交、推送、PR|再查同样门槛，仅做方案列明动作|实际提交、远端分支及 PR 对应；不新增 GitHub 评论/标签充当锁或正式台账|
|CI 与合并|核验指定候选 SHA 的必需 CI 全部通过，合并写前再查额度及停止状态|真实合并结果/提交，不用其他 SHA 或旧绿色检查替代|
|指定环境交付|部署写前再查额度、停止、期限、实际目标与当前状态，完成获批备份|实际部署版本、检查、用户可见验收与回滚材料分别记录|

范围改变、检查失败或撤销/停止时暂停受影响阶段；不绕过检查或扩大许可。结果未知先核验真实 thread/turn、提交、PR、部署现场及已有回执，不重放。停止是合作式请求，须核验活动任务实际终态才结束占用；不能因超时或停止回执自行释放。没有硬全局锁或跨平台 exactly-once 保证，不为此新增状态服务、GitHub 锁评论或标签。

只按预先批准且安全的条件回滚，并保护切换后的新数据；不盲目覆盖旧快照。结果报告沿原任务已批准的本人投递范围发送；原消息线程到期时可新开**结果用途**的通用通知，保留原任务/版本对应，不生成新的开发许可，也不因发报告恢复停止或过期任务。

## Hermes：待映射，未声称集成通过

未来接入需要逐项确认：身份与来源验证、GitHub 读写、原生定时/事件任务及期限关闭、开发任务创建/查询/停止、权威占用、额度与预算、可信结果及必要部署工具。仅拥有一条机器人长连接不能证明这些能力。

## 通用消息适配

独立 bridge 不读取 HiveFlow 规范来执行开发，也不解析 Issue 或执行批准。它可以提供业务无关的来源核验、固定本人/频道约束、通用请求与回复对应、可靠投递和去重。GitHub/研发业务由接收端智能体处理。

来源必须来自实际平台作者与桥接生成的可信对应记录，和正文中的自称、引用、转述区分。若只能读到一段无法验证来源的字符串，不能据此批准执行；改用已认证的本人入口或先完成受控来源映射，不新增绕过平台的授权接口。

**已接通：** 独立 bridge `5b476a2` 支持固定可信 bot 在固定私有频道的新根发送 `[wecom:notify]{"text":"正文"}`，不接受额外目标/身份/频道字段。本人用 `回复 N1 正文` 回到原根线程，后续同线程用 `[wecom:owner]正文` 延续；一个会话来回已实测。当前 TTL 3600 秒，不续期；期限固定东八区 `YYYY-MM-DD HH:mm:ss`，底层 epoch 不变。

回传首行为 `Owner conversation reply | N1`，metadata 为 `wecom_bridge_conversation_reply`，包含 `request_id` 和 `reply_code`，正文附桥接来源与不可信正文边界。接收智能体核验真实桥接 App、固定频道、原线程及可信对应，不能仅信这些文本或字段。短编号是会话关联，不是秘密、身份或执行授权；SDK 未证明有可靠原消息引用 ID，不能把引用内容或裸“同意”猜成关联。

**保留的隔离边界：** generic bridge 不处理旧 `[wecom:issue]`、`[wecom:execution-plan]`、`[wecom:execution-control]` 根；旧 kind=issue 线程仍失败关闭。旧业务表保留不迁移执行许可，旧精确执行命令不得重解释。通用 `[wecom:owner]` 依赖有效请求线程，主动发起使用 `[wecom:notify]`；没有无限会话或无限 TTL。

主动通知能力不再是当前阻碍。仍未进行并行逆序、到期与群问答的现场回归，也未执行真实开发；消息 ACK、用户可见、业务许可和执行完成分别记录，见 [验收边界](MIGRATION.md)。

## 验证与可靠性

- 用合成事项验证同一事件重复、相同任务重复唤醒、来源错误、停止后迟到结果、断线与重启、额度未知和截止。
- 核对共享账户额度的所有适用窗口、读取时刻和失败行为；Hermes 按其提供方另行映射，不能复制 dots 的额度数字。
- 先读历史再创建任务不提供原子认领；单个 automation、Slack 标记或 GitHub 评论/标签不等于全局互斥。没有已验证认领能力时，用一个控制器串行协调并保留人工核查，不承诺跨机器全局互斥。
- 当前 cloud_threads.create 未提供客户端幂等键。创建结果未知时必须查询真实 thread/turn 并核对关联，不因迁移释放占用或重试。
- 外部副作用不能由消息事务保证恰好一次。推送/部署结果未知时先读取真实现场，不能盲目重放；停止是合作式请求，不保证硬杀进程或即时中断。
- 平台任务延迟、共享额度并发消耗与消息窗口均需记录限制。规范文件不能保证准点关闭、始终保留固定余额或主动消息送达。
