# 智能体与工具适配说明

HiveFlow 是流程规范。适配是把责任映射到**已经存在且已获授权**的工具，不是开发一个新的 HiveFlow 业务服务。规范和适配表本身都不能授予权限；平台限制与实际能力优先。

## dots：已有能力与仍须核验的连接

依据本次协作已验证的能力，可采用以下分工；不意味着每个账户或未来宿主都具有同样能力：

|责任|dots 已验证可用的工具类别|接入前核验|
|---|---|---|
|定时唤起、截止关闭、事件响应|自身云端定时/事件任务|当前账户可用类型、最小间隔、截止/暂停效果和重复唤醒|
|Issue 台账与交付证据|已连接 GitHub 工具|正确私有仓库、真实作者、读写权限、计划与评论关联|
|消息接收和线程回报|已连接 Slack 工具|工作区、私有频道、实际 App 作者、桥接来源与线程身份|
|具体开发任务与回报|当前环境提供的 cloud_threads 等任务工具|目标环境、任务创建权限、确切任务身份、状态读取、中断和结果证据|

定时任务先读取明确有期限的会话授权，扫描范围内已同意事项并协调单任务占用，不让用户逐个手工入队。事件和评论是唤醒线索，必须重新核对当前授权、版本、状态及去重，不能仅凭控制文本创建开发任务。

工具名可按宿主映射；不把一个宿主的内部调用写成所有 dots 的永久公共 API。只读核验过额度接口不等于已接通执行链路；本轮没有新建任务、自动化或启用自动开发。

## Hermes：待映射，未声称集成通过

未来接入需要逐项确认：身份与来源验证、GitHub 读写、原生定时/事件任务及期限关闭、开发任务创建/查询/停止、权威占用、额度与预算、可信结果及必要部署工具。仅拥有一条机器人长连接不能证明这些能力。

如果宿主不支持某项能力，标记缺失并使用用户已批准的降级方式；例如保留手动协调，而不是编造已测试的自动调度、后台守护进程或共享锁。不得复用或接管当前 Hermes Bot ID、凭据或连接来填补缺口。

## 通用消息适配

独立 bridge 不读取 HiveFlow 规范来执行开发，也不解析 Issue 或执行批准。它可以提供业务无关的来源核验、固定本人/频道约束、通用请求与回复对应、可靠投递和去重。GitHub/研发业务由接收端智能体处理。

来源必须来自实际平台作者与桥接生成的可信对应记录，和正文中的自称、引用、转述区分。若只能读到一段无法验证来源的字符串，不能据此批准执行；改用已认证的本人入口或先完成受控来源映射，不新增绕过平台的授权接口。

**当前缺口：** generic bridge 不处理旧 [wecom:issue]、[wecom:execution-plan]、[wecom:execution-control] 根，旧 kind=issue 线程也不会恢复业务回传。通用 [wecom:owner] 依赖已有且未过 TTL 的通用请求，不能主动发起审批。

必须先证明业务无关的固定本人主动通知、正确回复关联和会话延续可用，再切生产。若需要桥接扩展，只能另行设计通用固定本人通知或通用会话机制，并保留原受众和认证边界；不得把 Issue 表、研发状态、许可或模式指令放回 bridge。本轮不实现该扩展。

## 验证与可靠性

- 用合成事项验证同一事件重复、相同任务重复唤醒、来源错误、停止后迟到结果、断线与重启、额度未知和截止。
- 核对共享账户额度的所有适用窗口、读取时刻和失败行为；Hermes 按其提供方另行映射，不能复制 dots 的额度数字。
- 先读历史再创建任务不提供原子认领；单个 automation、Slack 标记或 GitHub 评论/标签不等于全局互斥。没有已验证认领能力时，用一个控制器串行协调并保留人工核查，不承诺跨机器全局互斥。
- 当前 cloud_threads.create 未提供客户端幂等键。创建结果未知时必须查询真实 thread/turn 并核对关联，不因迁移释放占用或重试。
- 外部副作用不能由消息事务保证恰好一次。推送/部署结果未知时先读取真实现场，不能盲目重放；停止是合作式请求，不保证硬杀进程或即时中断。
- 平台任务延迟、共享额度并发消耗与消息窗口均需记录限制。规范文件不能保证准点关闭、始终保留固定余额或主动消息送达。
