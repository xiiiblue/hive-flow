# EXP-004：快速开始与采用方式

你可以先学习方法，再离线试用数据格式，最后决定是否为自己的项目接入真实平台。公开文档和离线演练不需要访问私有HiveOS；维护者核对上游原始字节才需要原有来源权限。

## 1.先运行本地检查

从仓库根目录运行README中的检查命令。Git与Python3.9+即可，Python工具无第三方包依赖。macOS先设置`TMPDIR=/tmp`。

加载演练会在临时Git目录构造私有仓库元数据、版本和错误输入；这是测试夹具，不是连接你的GitHub账号或修改远端。本仓库公开不改变原HiveOS适配中的固定身份校验。

## 2.准备一份关闭态提案

```sh
printf '%s\n' '{"operation":"initialize","record":null,"expectedBlobSHA":null,"observedBlobSHA":null}' | python3 -B scripts/hiveflow/adoption_record.py
```

输出包含`state=idle`、`executionEnabled=false`、`revision=0`。没有配置、事项或认领，不能用于业务执行。工具返回的是数据提案，真正的读写、旧SHA检查、独立读回、身份与授权核验由调用方负责。

已有非空或未知记录不能用这份空记录覆盖。其他采纳和认领演练直接运行`test_adoption_record.py`，其中所有事项与时间均为合成材料。

## 3.检查交付记录格式

建立一份自己的**合成**JSON文件，字段按[交付规范](../06-自动化/HFL-006-研发交付与原群回执.md)填写，再调用：

```sh
python3 -B scripts/hiveflow/validate_delivery.py demo-delivery.json
```

上面的文件名是你自行创建的输入，不是本仓库已有记录。一个可运行的最小例子如下；示例URL和提交仅用于结构检查，不是真实证据：

```json
{
  "schemaVersion": 1,
  "deliveryId": "demo-delivery-1",
  "repository": "example/project",
  "issue": 42,
  "pullRequest": 7,
  "commit": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "checks": [{"name": "synthetic-test", "status": "passed", "evidenceUrl": "https://example.invalid/check"}],
  "deployment": {"status": "not_required", "commit": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa", "evidenceUrl": "https://example.invalid/scope", "scope": "仅合成格式演练，不部署"},
  "acceptance": {"status": "passed", "evidenceUrl": "https://example.invalid/acceptance"},
  "publicSummary": "这是一份合成结构示例，不代表实际完成交付。"
}
```

格式通过不等于作者真实、证据存在、授权有效、用户收到或已读。更完整的拒绝场景见`test_delivery.py`。

## 4.为自己的项目采用方法

1. 先明确负责人、目标仓库与真实权限，保留目标项目已有的AGENTS、测试、审批和环境规则。
2. 选择反馈调查、登记、采纳、研发交付与回执中实际需要的部分，把职责和来源映射到自己的工具。
3. 手动启动先明确唯一事项、范围、交付终点、环境与验收。定时路径另需完整有界配置、真实启用和所需认领，不以阅读模板替代。
4. 只采用适用的数据格式和纯工具。采纳工具中固定的HiveOS仓库、控制位置与身份约束属于原实例；要改为其他实例，先形成明确适配方案并补正反向测试，不直接继承来源许可。
5. 在自己的隔离环境验证真实读写、来源绑定、未知结果、取消和恢复，再按获准范围启用。不要向真实群反复发送消息来试验格式。

其他宿主或模型是否具备所需能力，按实际接口、权限和证据核验。MacMini和dots是来源实例的工具组合，不是外部项目必须购买的产品配置。

## 5.公开参考与来源实例怎样区分

介绍手册和HFL规范保留来源实例的方法与边界。未收录的上游根规则、业务设计和运行证据可能仍是私有链接；它们不是离线试用的前置条件，也不在本仓库公开范围内。

公开版将示例环境写作“示例开发环境”，不提供机器地址；许可采用根LICENSE，贡献方式采用根CONTRIBUTING。带日期的来源接入记录不证明你的环境已接通。本仓库提供参考材料，实际采用时以自己项目的当前记录和真实权限为依据。
