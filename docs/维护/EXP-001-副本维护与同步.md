# EXP-001：副本维护与同步

本仓库保存HiveOS中HiveFlow内容的固定版本副本，方便独立阅读和离线检查。规范、介绍与业务使用同一上游版本；新规则仍先在HiveOS确认并修改。这里不重新维护一套执行规则，也不重新让外部任务追踪独立仓库。

## 收录什么，怎样记录来源

|内容|本仓库位置|维护方式|
|---|---|---|
|19份HFL正文、目录、目录规则及两份JSON|`docs/06-自动化/`|从选定HiveOS提交导出|
|12章介绍、3篇附录及目录|`docs/11-手册/05-自动化手册/`|与规范使用同一提交|
|离线工具、测试及局部忽略规则|`scripts/hiveflow/`|从同一提交导出，工具行为不在副本另改|
|首页、贡献与安全说明、EXP文档、导出工具与CI|根目录、`docs/维护/`、`scripts/`和`.github/`|本仓库维护|

[export-manifest.json](../../export-manifest.json)记录源仓库、完整提交、导出日期、收录目录和每份文件的两种SHA-256：`sourceSHA256`对应上游原始字节，`exportSHA256`对应本仓库实际文件。`adaptations`列出整理类型：`pinned-upstream-links`将未收录文件的相对链接固定到同一上游提交；`export-context`修正目录中的副本定位和手册中的一次性网站同步措辞；`pinned-entry-test-links`使加载测试能识别这种固定链接。

最后一项只调整测试中的入口路径比较：同一仓库、同一完整提交的固定链接可对应源文件路径，错误仓库、错误提交或越界路径仍拒绝。真实加载器、三条路线及必读集合不变，另有反向用例核对这些拒绝条件。业务数据工具与其余测试保持上游字节。

上游根AGENTS、ACDL及其他手册没有复制进来，链接需要上游原有访问权限。尤其不能用本仓库根AGENTS替代加载清单所指的HiveOS根AGENTS。清单中的`repo`、业务来源与加载路线保持HiveOS身份；它们是可研究的规则副本，不是允许将真实任务迁到本仓库的配置。

HFL正文的状态、原日期及验收事实属于来源提交；HFL-018的迁入摘要保存的是更早一次迁入的字节，不随当前同步重算。当前导出摘要另存，不能混用。源码、运行记录和个人配置不会因为在上游存在就进入副本。

## 更新一次副本

1. 核对本仓库的main、完整HEAD、远端与工作区差异，先处理未知改动。同步前确认上游规范与介绍已经按依赖顺序完成必要修订和检查，选择明确的完整提交。
2. 核验本地HiveOS的origin是`xiiiblue/hive-os`，确认所选提交及公开范围。同步工具只读取该提交的Git对象，不读取未提交业务文件，不联网拉取，也不写上游。
3. 在本仓库根目录运行下列命令。将变量替换为实际本地位置及已选择的完整提交，不从示例推定最新版本。

```sh
export TMPDIR=/tmp
python3 -B scripts/sync_from_hiveos.py --source "$HIVEOS_SOURCE" --commit "$HIVEOS_COMMIT"
python3 -B scripts/sync_from_hiveos.py --source "$HIVEOS_SOURCE" --commit "$HIVEOS_COMMIT" --check
```

4. 审阅实际差异及来源清单。工具拒绝已有副本的手工差异、清单外文件、路径越界或符号链接时，先查明原因，不删除来源摘要来强行覆盖。上游新增文件类型或目录、目录措辞发生变化时，重新审阅收录与整理规则。
5. 运行下节检查，记录实际输入和结果，按当前授权提交推送；核对对应提交的CI。同步不改原生任务、宿主提示、权限、运行状态或网站；若任务同时要求这些操作，分别核验各自实际结果。

更新中不需要恢复旧英文正文或退役应用。旧路径留在HFL-018和Git历史供追溯，业务宿主继续从HiveOS的新入口读取。

## 检查什么

```sh
export TMPDIR=/tmp
python3 -B scripts/check_repository.py
python3 -B scripts/hiveflow/test_spec_loading.py
python3 -B -m unittest discover -s scripts/hiveflow -p 'test_*.py'
python3 -B scripts/test_export.py
git diff --check
```

全仓检查核对导出摘要、覆盖范围、本地链接、章节锚点和常见敏感形态。加载检查验证固定来源、三条路线、缓存、旧路径及拒绝条件；纯数据测试覆盖采纳状态、idle、交付格式、查询边界和源码过滤；副本测试覆盖改动保护、来源计划与路径边界。

默认检查使用Git与Python标准库，不发送消息、不建Issue、不访问真实控制记录。接入演练另按HFL-013选择已有本地桥接源码与精确依赖缓存，不能用它冒充真实业务联调。文档检查也不核验远端链接是否可访问，更不证明Git历史、权利和第三方元数据都已可公开。

## 修正、恢复与交付

发现规范或工具行为问题，记录偏差，先在HiveOS修正并取得新的完整提交，再导出；已知副本维护工具的问题可在本仓库修复并测试。需要恢复时选择此前已验证的来源提交重新同步并创建新提交，不改写共享main，不恢复已退出上游的设计。

交付说明写清上游完整提交、整理范围、必要检查、失败与未运行项、本地及远端提交状态。未发生的真实平台同步、公开发布或业务验收不能写成已完成。
