# 新使用者快速开始

HiveFlow 是规范，不是要安装的业务服务。先分清三层：规范说明如何调查、决定、实施和交付；Dots 是当前理解/协调的适配；独立 wecom-slack-bridge 只负责消息传输。GitHub Issues 记录事项，不能充当执行锁或授权来源。

不需要旧聊天、维护者个人账号或固定机器目录。使用自己的获授权账户、项目、工作群及环境；具体模型以账户和平台支持为准。规范仓库目前私有，clone 需要已有读取权限；[公开网站](https://www.bluexiii.com/flow/)提供审阅后的内容快照，不等于已获得私有仓库权限。

## 1. 取得文件并检查规范

需要 Git、Python 3.9+；要演练桥接还需要 Node.js24.x、npm 及本地已缓存的锁定依赖。下面的仓库下载是准备步骤；后面的演练不联网。

```sh
git clone https://github.com/xiiiblue/hive-flow.git
git clone https://github.com/xiiiblue/wecom-slack-bridge.git
cd hive-flow
python3 scripts/check_docs.py
```

没有规范读取权限时先阅读公开指南或联系负责人，不借用他人的 token。两份源码独立维护；本仓库没有 npm start，也不提供模型、消息机器人或新的权限服务。

## 2. 先跑全新隔离演练

```sh
python3 scripts/rehearse_offline.py --bridge-source ../wecom-slack-bridge --report rehearsal-result.json
```

工具新建临时目录，复制规范文档与检查工具、从本地桥接固定提交导出干净源码，不复制现有 .env、node_modules 或运行状态。只从 npm 内容缓存读取**锁文件所指公开依赖的精确完整性内容**，装入隔离缓存，再以 offline/ignore-scripts 安装；不复制 npm 配置、请求头或其他缓存。缓存不齐时明确报告该步骤未完成，不自动联网补齐。

随后检查空配置应拒绝、合成占位配置可通过语法检查；运行桥接既有离线测试，以及模拟群反馈→Slack 根→模拟事项登记回执。模拟 GitHub 记录只是本地 JSON，Dots 模型、真实建单、群消息和权限判定均未调用。最后在抛弃式状态目录验证备份、sending→unknown 恢复、同版本状态存储模块的目录切换及回退保留新增记录。完整结果和未运行项写入报告；临时目录结束后删除。

报告中的 passed 仅针对明确的离线步骤，不是端到端验收或硬权限隔离证明。没有预热缓存的新机器可以先在获准网络环境按桥接说明安装固定依赖，再回到本步骤；本轮演练不自动取得网络或新权限。

## 3. 看一次反馈与决定记录

群用户按 [用户指南](USER_GUIDE.md)自然说明现象，例如“导出只到第一页，预期全部结果”。协调方核对范围、调查并补问关键缺口；需要改动且获准时查重登记。桥接不建 Issue，不解释采纳或批准。

演练在临时目录生成合成登记草稿，结束后删除；报告保留模拟结果。可按 [事项收尾](ITEM_LIFECYCLE.md)逐步核对：待评估保持 open；采纳不授予实施；暂缓保持 open；拒绝需先核验回写/关闭授权；交付需核实实际验收，不能仅凭合并或进程健康关单。正式台账不自动更新。

## 4. 准备自己的接入（演练不执行）

|准备项|由谁提供/核验|
|---|---|
|协调方|选择自己的 Dots 或其他获准宿主及可用模型；按 [适配说明](ADAPTERS.md)验证能力，不沿用维护者账户配置|
|负责人决策入口|唯一可核验的本人受控通道；当前 Dots 适配为本人主对话，群不能授予实施权限|
|项目与 Issues|固定仓库、可见成员、允许新建/回写/关闭的具体范围；只读扫描与群入口不自动获得写权限|
|工作沟通|管理员接入并授权的工作群、私有 Slack 频道、真实桥接与响应方身份；新群另核准|
|独立桥接|自己的机器人与 App 配置；新安装不复用其他运行服务的 Bot ID，不创建竞争连接|
|环境诊断/交付|按实际任务核验受限查询与部署边界；不从公开示例获取机器、文件或凭据权限|

桥接的 [配置指南](https://github.com/xiiiblue/wecom-slack-bridge/blob/main/docs/CONFIGURATION.md)、[消息协议](https://github.com/xiiiblue/wecom-slack-bridge/blob/main/docs/PROTOCOL.md)和[安装维护](https://github.com/xiiiblue/wecom-slack-bridge/blob/main/deploy/README.md)独立维护。新使用者须先核对固定发布提交再跟随对应文档，不以浮动 main 作为已验证部署版本。

只有接入、受众、发送范围与启动均获准后，才在自己的环境安全填写配置并启动服务。凭据只在受控运行环境保存，不贴聊天或纳入规范；此演练既不申请权限，也不执行启动。真实检验须覆盖机器人消息及本人线程回复触发响应方、显式路由、错误来源、实际可见和真实往返。

## 5. 故障与升级回退

按桥接维护说明先停止唯一写者、记录代码版本并一致备份；不能只复制正在写的主 SQLite 文件。pending 可恢复，sending/不确定结果先核验，不改回 pending 重放。回退先保留切换后的新状态，证明旧代码兼容后优先退代码，不能用旧快照覆盖新增消息与去重记录。

离线工具只验证同一固定版本状态存储模块的目录切换和状态保留、备份副本可读，以及模拟 unknown 不重发；**不验证跨版本迁移、真实进程中断、平台重连或生产恢复**。这些需在独立明确授权和隔离条件下按 [验收清单](ACCEPTANCE.md)验证，不在用户现有服务上试错。
