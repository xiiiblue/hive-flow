# 12.接入与验证：从离线演练到真实使用

> 文档状态：Review
>
> 责任角色：Director
>
> 本文负责：解释接入准备、离线演练、分层验证和已知能力的证据范围

## 1.先准备一种能解释清楚的接入

开始使用HiveFlow，可以先选择固定项目、明确受众和较小的调查范围，把反馈、决定、实施和结果各自放到可核验的位置。

HiveFlow提供规范、指南和离线辅助。模型能力来自已有宿主，事项能力来自获准仓库与工具，消息能力来自已获准的企微适配器及Webhook。取得文档不会自动取得这些账户或运行权限。

首次接入以“能准确说明范围和结果”为目标，不需要一开始就启用自动研发。

## 2.接入前准备哪些条件

|准备项|需要落实的内容|
|---|---|
|项目与记录|准确仓库、可见成员，以及允许读取、新建、回写或关闭的范围|
|协调方|获准宿主、可用模型、资料访问和真实响应方身份|
|负责人入口|唯一可核验的决策通道，直接Codex任务由实际执行会话核验|
|工作沟通|已授权工作群、固定传输来源和允许公开的内容|
|研发环境|本地项目、工具、检查方式及获准交付目标|
|消息与通知|自己的真实事件、获准受众、私有来源与发送账、未知恢复方式|

新使用者使用自己的授权配置，不借用维护者个人账号或凭据。外部接入、发布与权限变化仍按实际任务确认，不能从公开教程复制地址和密钥。

## 3.只检查规范怎样开始

在已取得读取权限的HiveOS工作目录中，可以先检查文档和加载规则，不需要运行Hermes、消息连接或业务服务。

```sh
python3 -B scripts/hiveflow/check_docs.py
python3 -B scripts/hiveflow/test_spec_loading.py
```

文档和离线辅助使用Python标准库；在本仓库工作还需遵守当前根规则和锁定工具链。macOS运行验证前设置`TMPDIR=/tmp`。

HFL-013的桥接源码与依赖缓存演练属于旧Dots适配，仅作历史回归；当前Hermes检查按HFL-022分别安排。缺少依赖时保留未完成，不为了通过演练自动联网补齐或读取现有运行配置。

## 4.离线演练实际能证明什么

隔离演练使用临时目录、合成消息、占位配置和模拟事项，核对字段、关联、状态、去重及同版本恢复行为。它不调用真实模型、建单、发群或证明工具权限。

采纳计划辅助只校验数据并输出提案，源码快照辅助只处理已取得的数据。execution_control与source_evidence另有调用gh的私有控制入口，不能统称为纯离线工具；离线测试使用合成存储，不调用这些真实API入口。公开副本保持参考用途，真实运行仍加载业务项目规则。

离线演练通过，说明所覆盖的合成条件得到预期结果。真实身份、平台拒绝、跨群隔离、跨版本恢复和在途调用，仍需相应现场证据。

## 5.按D、S、L分别登记验证

|层次|含义|典型证据|
|---|---|---|
|D：文档设计审查|规则与案例是否清楚、一致|规范、输入输出、正反例与链接检查|
|S：合成演练|隔离合成输入下是否符合预期|离线测试、临时记录、预期停止断言|
|L：现场联调|真实宿主与获准环境中实际怎样工作|真实身份、版本、调用、拒绝、送达或恢复证据|

各层按宿主、时间、对象和范围分别报告。另一个工具或环境通过过，不意味着当前宿主也通过；平台返回的消息确认也不能替代业务验收或用户已读。

本书的流程图和合成案例属于说明材料，没有因为被写出来就获得S层或L层通过结果。

## 6.现有材料支持哪些结论

以下据10月30日接入记录及本轮2.0评审整理，不作为持续在线声明。

|主题|已有依据|尚未完成的验证|
|---|---|---|
|规范与离线工具|同版本加载、选单、占用、接棒和未知状态的合成检查|不能证明模型遵从、真实权限或全部现场副作用|
|Hermes企微接入|本人确认QueenBee接通，旧bridge停用|本人／非本人／外群、会话与工具隔离、持久防重复建单|
|Webhook|小测试群接口接受且本人确认收到；正式群接口接受|正式群实际可见、成员提醒、跨天及重启恢复|
|双机研发|Hermes协调远程开发机，Director直接控制MacMini；已有共享记录工具|Hermes派发PR及完整交付、两台实际机器竞争与接棒、长任务停止与恢复|
|周期选单|有模板和选单工具；MacMini两项原生任务记录为暂停|Hermes实际配置与周期全链路；旧Dots云端任务启停未知|

旧桥接、Dots入口切换与历史HTTP回执证据不能转为Hermes已通过。2.0说明规范代际，不表示上述待验收项已经完成；当前实际状态仍须按宿主、日期与任务核对。

## 7.真实验证怎样安排

真实验证从本人明确的单项范围开始，使用合成账号或获准真实事项，核对来源、受众、工具权限和恢复条件。每次只证明实际经过的路径。

例如，确认一条Webhook回执被原群收到，可以记录该次收到；不能顺带宣布跨天、重启去重和所有其他群均可用。通用任务每次最多一单，不回放创建边界前历史事项；单槽试验仍沿用其单项限制。

新群接入、新写权限或生产变化分别核验，不能借“验证”扩大环境或受众。没有实际完成的用例保留未验证，不用演示图或成功日志替代。

共享占用的真实GitHub竞争、另一机器接棒及在途请求的恢复仍分别核验；同机两个进程的测试不能冒充真实第二台机器验收。日常任务按基础路线读取，通知和接棒协议到达对应阶段才加载，工具自动生成读取证据。

## 8.升级和恢复为什么另看证据

规范更新、任务配置保存、代码部署、消息连接和业务可用是不同事实。更新规范后，只在已有授权内同步受影响提示，并独立读回；不能因为Git已经推送，就声称所有任务已经采用新版本。

运行状态升级需要核对唯一写入者、一致备份和兼容恢复。旧快照不能覆盖升级后的新增消息、去重记录或业务数据；恢复过程也不把未知发送改回待发重放。

本章提供选择验证范围的方法。实际环境操作继续从对应环境文档和工具入口核验，不把教程当作运行命令清单直接执行。

## 远程调度先验证哪些环节

先在Hermes手动运行一单PR待审，再运行一单完整交付，最后验证连续多轮。每一步分别核对真实执行身份、工作树、共享占用、结果证据和发送账；已通过的单次结果不能替代故障恢复。

重点验证重复唤醒不派第二单、启动超时不重启、宿主重启能找回原Codex、旧PID不会误认新进程、窗口和待审上限可停止派发、本人停止后在途结果仍可核实。没有可靠完成事件时先保留定时检查，不声称即时接续。规范场景见[HFL-012远程调度验收](../../06-自动化/HFL-012-检查与验收清单.md#hermes远程调度验收)。
